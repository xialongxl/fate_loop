# 《命运轮回：Boss Rush》开发计划书

## 1. 项目概述

**项目名称**：命运轮回（英文名：Fate Loop） 
**项目类型**：Roguelike / Boss Rush / 弹幕射击 / 策略构建  
**目标平台**：现代浏览器（桌面端优先，兼容移动端触控）  
**技术栈**：  
- **语言**：JavaScript（ES2022+）  
- **构建工具**：Vite 7  
- **渲染方案**：Canvas 2D / PixiJS（推荐 PixiJS 以获得高性能 WebGL 渲染，同时保留 Canvas 2D 回退）  
- **状态管理**：自研轻量级事件驱动 + 不可变状态  
- **音频**：Howler.js  
- **本地存储**：IndexedDB  
- **版本控制**：Git + 语义化提交  

**项目简介**：  
玩家将扮演一名“序列编织者”，在连续 Boss 战中生存。游戏核心为：  
- **Boss Rush**：连续挑战多场 Boss 战，Boss 顺序与词缀随机生成。  
- **弹幕**：Boss 释放密集但可读的弹幕，玩家需精准走位。  
- **自定义技能序列**：玩家可在战前编辑一个自动释放的技能序列（类似“编程技能链”），战斗中技能按序列循环触发，玩家专注于移动与时机判断。

## 2. 核心玩法设计

### 2.1 游戏循环
1. **准备阶段**：  
   - 查看下一场 Boss 的随机信息（名称、弹幕类型、词缀）。  
   - 编辑/调整自定义技能序列（从已解锁技能池中拖拽排列）。  
   - 消耗“灵魂碎片”购买一次性增益或强化技能。  
2. **战斗阶段**：  
   - 进入封闭竞技场，Boss 按阶段释放弹幕。  
   - 玩家角色自动按自定义序列释放技能，玩家仅控制移动（鼠标/键盘/触控）。  
   - 玩家需在弹幕间隙中寻找输出窗口，同时管理技能资源（能量/冷却）。  
3. **结算阶段**：  
   - 击败 Boss 后获得随机技能、灵魂碎片、被动道具。  
   - 生命值不自动回满，仅少量恢复；死亡则本轮结束，进入 meta 成长结算。  

### 2.2 Roguelike 元素
- **随机性**：  
  - Boss 顺序、词缀（如“弹幕加速”“分裂弹”“地面燃烧”）随机。  
  - 战后技能三选一，技能稀有度随机。  
  - 竞技场环境随机（障碍物、传送带、减速区域）。  
- **永久死亡**：  
  - 单局内角色死亡即结束，但会获得“记忆碎片”用于解锁永久升级（如初始生命、技能槽位、初始技能池）。  
- **构建深度**：  
  - 技能之间存在“连携”标签（如“冰霜→火焰”触发爆炸），自定义序列需考虑顺序与触发条件。  

### 2.3 自定义技能序列（核心创新）
- **序列编辑器**：  
  - 采用**节点式/队列式**界面，玩家将技能图标拖入 3~8 个槽位，形成循环序列。  
  - 每个技能可设置触发条件（如“当附近弹幕数>5时”“每 3 秒”“能量>50 时”）。  
  - 支持“分支”与“优先级”：例如“若生命<30%则优先释放治疗技能”。  
- **战斗自动执行**：  
  - 序列按固定时钟或事件驱动逐槽检查，满足条件则释放。  
  - 玩家无法手动打断序列，但可通过移动改变触发条件（如远离弹幕以降低触发阈值）。  
- **资源管理**：  
  - 技能消耗“能量”，能量随时间回复、命中弹幕/敌人回复。  
  - 序列中可插入“充能”动作，延迟释放但增加后续技能威力。  

### 2.4 Boss 设计与弹幕系统
- **Boss 结构**：  
  - 每个 Boss 拥有 3~5 个阶段，阶段切换时改变弹幕模式与移动逻辑。  
  - 弹幕类型：定向弹、扇形弹、螺旋弹、追踪弹、激光、弹幕墙、环境弹幕等。  
  - 所有弹幕需**可读性设计**：颜色区分敌我、弹道预描线、危险区域提示。  
- **弹幕系统要求**：  
  - 同时支持 2000+ 弹幕对象，60 FPS。  
  - 使用对象池 + 空间哈希网格碰撞检测。  
  - 弹幕模式使用**数据驱动**：JSON 定义弹幕发射器参数（发射角、速度、加速度、生命周期、图案）。  

### 2.5 玩家角色
- **移动**：八方向，速度恒定，带有轻微惯性。  
- **受击判定**：仅中心小圆点（判定点），非整个角色贴图，提升公平性。  
- **生命与资源**：生命值、能量值、护盾（临时）。  
- **角色成长**：局内通过技能与被动道具提升，局外通过 meta 升级。

## 3. 技术架构

### 3.1 技术选型理由
- **ES2022+**：  
  - 使用类字段、私有字段（`#`）、静态初始化块、`Array.prototype.at()`、`Object.hasOwn()`、顶层 `await` 等，提升代码可读性与安全性。  
  - 利用 `Error cause` 增强异常链追踪。  
- **Vite 7**：  
  - 毫秒级冷启动、HMR 热更新，适合快速迭代。  
  - 生产构建基于 Rollup，支持代码分割与 Tree Shaking。  
  - 通过 `import.meta.glob` 动态加载弹幕模式 JSON 与技能模块。  
- **渲染层**：  
  - 优先采用 **PixiJS v8**（WebGL 渲染，自动回退 Canvas），提供高性能精灵与粒子系统。  
  - 若坚持零依赖，可用 Canvas 2D + `OffscreenCanvas` 分离渲染与逻辑，但开发量较大。  
- **架构模式**：  
  - **ECS（Entity-Component-System）** 或 **轻量级 OOP**：建议采用 ECS 思路管理实体（子弹、敌人、特效），逻辑与渲染分离。  
  - 核心逻辑运行在固定时间步长（如 60Hz 逻辑 tick），渲染插值。  

### 3.2 目录结构（规划）
```
src/
  core/          # 游戏循环、事件总线、状态管理
  ecs/           # 实体、组件、系统
  systems/       # 移动、碰撞、弹幕发射、技能执行、AI
  components/    # 数据组件定义
  renderer/      # PixiJS 场景、精灵管理、特效
  ui/            # 序列编辑器、HUD、菜单
  data/          # 技能、Boss、弹幕模式 JSON
  utils/         # 数学、对象池、空间哈希
  meta/          # 永久升级、存档
  assets/        # 图片、音频、字体
  main.js
```

### 3.3 核心系统设计
- **游戏循环**：  
  - `requestAnimationFrame` 驱动渲染，逻辑更新使用固定时间步长（1/60s），避免帧率波动影响弹幕判定。  
- **事件总线**：  
  - 全局 `EventEmitter`，用于系统间解耦通信（如“玩家受伤”“Boss 阶段切换”“技能释放”）。  
- **弹幕对象池**：  
  - 预分配子弹对象，避免 GC 抖动。  
  - 每个子弹包含：位置、速度、加速度、生命周期、所属阵营、碰撞半径、渲染引用。  
- **碰撞检测**：  
  - 玩家判定点 vs 敌方子弹：空间哈希网格，只检测玩家所在格子及邻格。  
  - 玩家技能 vs Boss/敌方子弹：使用圆-圆/圆-矩形碰撞。  
- **技能序列引擎**：  
  - 序列表示为**有向图/数组**，每个节点包含技能 ID、触发条件、优先级。  
  - 每逻辑帧评估一次：按优先级检查各节点条件，选取第一个满足的节点执行，然后进入冷却/能量扣除。  
  - 支持“重置循环”与“单次触发”模式。  
- **Boss AI**：  
  - 使用**有限状态机（FSM）**管理 Boss 阶段行为。  
  - 每个阶段定义：移动模式、弹幕发射器列表、切换条件（血量百分比/时间）。  
  - 弹幕发射器通过**数据驱动**生成，支持组合与嵌套。

## 4. 功能模块划分

### 4.1 核心战斗模块
- 玩家控制器（移动、碰撞）  
- 技能系统（释放、冷却、能量、连携）  
- 弹幕系统（发射、更新、碰撞）  
- Boss 管理（生成、阶段、AI、掉落）  
- 战斗场地（边界、障碍物、环境效果）  

### 4.2 自定义序列编辑器
- 技能槽位 UI（拖拽、排序、条件编辑）  
- 序列验证（能量平衡、冷却冲突）  
- 序列预览（模拟释放时间轴）  
- 预设序列保存/加载  

### 4.3 Roguelike 系统
- 随机生成器（Boss 队列、词缀、技能掉落）  
- 局内成长（技能升级、被动道具）  
- 局外 meta 成长（记忆碎片、永久解锁）  
- 存档系统（当前 run 状态、meta 进度）  

### 4.4 UI/UX
- 主菜单、设置、图鉴  
- 战斗 HUD（生命、能量、序列状态、Boss 血条）  
- 结算界面（奖励选择、数据统计）  
- 序列编辑器界面  
- 弹幕可读性辅助（危险区域提示、弹道预描线开关）  

### 4.5 音频与视觉
- 音频管理器（BGM、音效、音量控制）  
- 粒子特效（爆炸、命中、技能释放）  
- 屏幕震动、慢动作（Boss 击败瞬间）  
- 动态背景（随 Boss 阶段变化）

## 5. 开发计划与里程碑

### 阶段 0：原型验证
- 搭建 Vite 7 + ES2022 基础项目。  
- 实现玩家移动与基础弹幕发射。  
- 实现一个简单 Boss 与自定义技能序列的最简闭环（3 个技能、1 个 Boss、1 个竞技场）。  
- 验证弹幕性能（2000 弹幕 60FPS）。  

### 阶段 1：核心战斗完善
- 完善弹幕系统：多种弹幕模式、对象池、空间哈希。  
- 实现 3~5 个 Boss，每个至少 3 阶段。  
- 技能系统：10~15 个基础技能，支持连携标签。  
- 自定义序列编辑器基础版（队列式，无分支）。  
- 基础 HUD 与 Boss 血条。  

### 阶段 2：Roguelike 结构
- 随机 Boss 队列与词缀系统。  
- 战后奖励三选一、灵魂碎片商店。  
- 局外 meta 成长（记忆碎片、永久升级）。  
- 存档与读取。  

### 阶段 3：序列编辑器高级功能
- 节点式序列编辑器（拖拽、连线、条件分支）。  
- 触发条件可视化编辑。  
- 序列模拟与 DPS 预估。  
- 预设序列管理。  

### 阶段 4：内容填充与打磨
- 扩充至 8~10 个 Boss，20+ 技能，15+ 被动道具。  
- 添加更多弹幕模式与词缀。  
- 完善音频、粒子特效、屏幕震动。  
- 难度曲线调整与平衡性测试。  

### 阶段 5：测试与发布
- 内部测试（玩法、性能、兼容性）。  
- 修复 Bug，优化加载时间与内存占用。  
- 部署至静态托管（Netlify/Vercel/GitHub Pages）。  
- 收集反馈并规划后续更新。

## 6. 质量保证与测试

### 6.1 测试策略
- **单元测试**：使用 Vitest 测试纯逻辑模块（序列引擎、碰撞检测、随机生成器）。  
- **集成测试**：测试技能与弹幕交互、Boss 阶段切换。  
- **性能测试**：使用 Chrome DevTools Performance 面板监控帧率、内存、GC 频率。  
- **平衡性测试**：通过自动化模拟战斗（AI 控制玩家）收集胜率数据。  

### 6.2 性能指标
- 目标 60 FPS，弹幕数 ≥2000，移动端 ≥30 FPS。  
- 首屏加载 <5s（含资源）。  
- 内存占用 <500MB（桌面端）。  

### 6.3 兼容性
- 支持 Chrome、Firefox、Edge 最新两个版本。  
- 移动端 Safari / Chrome 基础适配（触控移动、UI 缩放）。

## 7. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 弹幕性能瓶颈 | 高 | 早期性能测试；使用对象池、空间哈希；必要时降低弹幕数量或简化渲染。 |
| 自定义序列编辑器复杂度高 | 高 | 分阶段实现：先队列后节点；提供模板与默认序列降低上手门槛。 |
| Boss 设计重复 | 中 | 建立弹幕模式库，通过组合与词缀生成差异；引入环境机制。 |
| 技能平衡性差 | 中 | 自动化模拟 + 玩家反馈；设计连携标签限制强力组合。 |
| 移动端触控体验差 | 中 | 提供虚拟摇杆与自动瞄准选项；UI 适配。 |
| 开发周期过长 | 高 | 严格遵循里程碑，优先实现最小可玩版本；功能裁剪。 |

## 8. 未来扩展方向

- **多人合作模式**：两名玩家共享自定义序列，协作挑战。  
- **创意工坊**：允许玩家自定义 Boss 弹幕模式与技能序列并分享。  
- **赛季系统**：定期更新 Boss 池与词缀，引入排行榜。  
- **控制器支持**：兼容手柄。  
- **更多 Roguelike 元素**：地图探索、事件房间、精英怪。

## 9. 结论

本项目结合 Boss Rush 的紧凑节奏、弹幕射击的紧张感与自定义技能序列的策略深度，具备较高的玩法创新性与复玩性。使用 ES2022+ 与 Vite 7 可保证开发效率与代码质量，同时通过分阶段开发与严格测试控制风险。计划书覆盖从原型到发布的完整流程，可作为后续开发的指导文档。
