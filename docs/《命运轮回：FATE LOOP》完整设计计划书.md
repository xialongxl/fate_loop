## 第一章：项目总览

### 1.1 项目名称
（留空，由开发者自行定名）

### 1.2 项目一句话定位
一款**纯文字、纯单机、模组驱动**的 Roguelike 自动战斗工具。玩家在**网格式节点地图**上自由探索，遭遇敌人后触发**自动战斗**，通过编排技能序列优化战术，挑战随机生成的每一层地图。

### 1.3 核心玩法描述（完整版）
1. **启动游戏**：系统自动生成一个随机种子（无需玩家输入），据此生成第一层地图。种子输入框为可选高级功能，供玩家复现特定地图布局。
2. **地图探索**：玩家面对一张**网格化节点地图**（类似《明日方舟》集成战略“黑流树海”）。地图由起点、战斗节点、精英节点、休息节点、商店节点、事件节点、出口节点和死路节点组成。玩家通过**鼠标点击**向上下左右相邻节点自由移动，**无行动力消耗**，可无限次往返已探索区域。
3. **战斗触发**：首次进入战斗节点（普通/精英）时，自动进入**自动战斗**模式。战斗基于玩家预先编排的 GCD/oGCD 技能序列进行。
4. **战斗结果**：胜利后节点标记为“已清理”，今后路过不再触发战斗；失败则本次探索永久结束（永久死亡），显示结算面板。
5. **节点清理与推进**：普通/精英战斗节点清理后变为空地；休息节点使用一次后失效；出口节点抵达后进入下一层，生成全新地图，不可返回上一层。
6. **无限试错**：移动不消耗任何资源，玩家可反复在已探索区域调整技能序列，重新挑战未清理的战斗节点。但每场战斗本身只能打一次——输即死，赢即永久清理。
7. **地图交互**：地图内嵌于页面左侧，支持鼠标滚轮缩放（0.5x~2.0x）、拖拽平移、双击复位。

### 1.4 目标用户
- 喜欢策略构筑、数值优化的玩家
- 喜欢探索随机地图、规划路线的 Roguelike 爱好者
- 模组开发者（希望注入新技能、新怪物、新地图生成逻辑）

### 1.5 非目标（明确排除）
- 不提供实时操作（无走位、无弹幕、无QTE）
- 不提供任何联机、排行榜、上传功能
- 不提供图形化战斗画面（仅文字、数字、进度条）
- 不强制玩家输入种子

## 第三章：核心设计哲学（四条铁律）

### 3.1 数据驱动，杜绝硬编码
所有技能、怪物、地图生成逻辑均为符合契约的数据结构或函数定义。引擎核心代码中不得出现任何 `if (nodeType === 'xxx')` 特判。

### 3.2 模组即原生（自举）
官方提供的所有内容（技能、怪物、地图生成器）均以模组形式存在于 `/mods/official/` 目录。第三方模组与官方模组在加载机制上无任何区别，仅通过文件路径优先级区分。

### 3.3 确定性至上（种子即命运）
- 同一种子 → 同一层地图的节点布局、节点类型、怪物配置完全一致。
- 同一种子 + 同一技能序列 → 战斗结果（总逻辑耗时、胜负）完全一致。
- 绝对禁止使用 `Math.random()`、`Date.now()`、`performance.now()` 参与地图生成或战斗逻辑。

### 3.4 纯单机离线
不发起任何网络请求，不上传任何数据。种子仅用于本地地图复现，不依赖任何外部服务。


## 第四章：时间系统规格（无 Tick，纯虚拟毫秒）

### 4.1 虚拟时钟定义
引擎内部维护一个整数变量 **`virtualTime`**，单位为**毫秒**。它不依赖任何物理时钟，完全由引擎自身累加。

### 4.2 技能冷却与 GCD 的存储方式
- 模组作者定义技能时，直接以**秒**为单位书写（如 `cooldown: 3.0`）。
- 引擎加载时，自动转换为整数毫秒（`cooldownMs = Math.round(3.0 * 1000)`），存入技能定义中。
- 所有 CD、GCD、Buff 持续时间在运行时均为**整数毫秒**，无浮点数参与。

### 4.3 时间推进规则（三种模式）
- **1x 观赏模式**：每帧（`requestAnimationFrame`）固定推进 **16 毫秒**。
- **4x 加速模式**：每帧固定推进 **64 毫秒**。
- **MAX 瞬间结算模式**：进入同步 `while` 循环，`virtualTime` 以 16ms 为步长疯狂累加，直到战斗结束，物理耗时仅几十毫秒。

### 4.4 冷却判定逻辑（纯整数比较）
每个实体维护一个 `lastCastTime`（整数毫秒）。  
释放条件：`if (virtualTime - lastCastTime >= cooldownMs) { 释放; lastCastTime = virtualTime; }`

### 4.5 与物理时间隔离的原因
- 物理时间受系统时钟篡改、NTP 校准、后台标签页节流影响，破坏确定性。
- 物理时间无法“加速”（MAX 模式无法瞬间模拟秒级 CD）。
- 浮动累加在不同 CPU 上存在微小舍入差异。

## 第六章：地图生成与探索（完整规格）

### 6.1 种子与地图生成
- 若玩家未输入种子，系统自动生成随机种子（基于 `Date.now()` 混合一次后丢弃，仅用于生成初始种子）。
- 种子输入框默认显示当前种子，玩家可修改并确认重置地图。
- 地图生成完全由种子驱动，同种子同层生成完全一致。

### 6.2 生成算法（网格化，黑流树海风格）

**第一步：确定网格尺寸**
由种子决定，范围 8×8 ~ 14×14 网格。

**第二步：起点生成**
起点固定在地图中央偏下区域（约 60%~70% 高度位置）。起点向上下左右四个方向的连接数量由种子决定（1~4 条均可，不固定四方通）。

**第三步：随机延伸**
从起点开始，以概率向四个方向延伸新节点。延伸概率随距离起点越远而递减，形成“近密远疏”的自然分布。每个新节点有概率终止延伸，形成死路（约 30% 节点为死路）。死路节点无任何事件，仅表示此路不通。

**第四步：节点类型分配（排除起点和死路后）**
- 普通战斗：45%
- 精英战斗：12%
- 休息：12%
- 商店：8%
- 事件：8%
- 出口：固定 1 个（地图边缘最远位置）

**第五步：连通性保证**
从起点出发，至少存在一条路径可到达出口。所有非死路节点均与主通路连通（不存在孤岛）。

### 6.3 玩家移动交互（纯鼠标）

- **点击相邻节点**：玩家只能移动到与当前节点**上下左右相邻**的节点。
- **点击非相邻节点**：无反应（或显示“路径不通”简短提示）。
- **节点状态反馈**：
  - 未揭示：显示为 `?`
  - 已揭示但未进入：显示类型图标
  - 已进入：高亮边框
  - 已清理：打勾标记 + 淡化显示
- **无行动力消耗**：移动不消耗任何资源，可无限次往返。

### 6.4 战斗触发规则

- 首次进入 `combat` / `elite` 节点时，自动触发战斗。
- 战斗胜利 → 节点标记 `isCleared = true`，今后路过不再战斗。
- 战斗失败 → 本次探索结束（永久死亡），显示结算面板。
- 玩家可在进入战斗前随时点击其他已探索节点返回，调整技能序列后再回来挑战。

### 6.5 地图视口控制（内嵌式）

- **缩放**：鼠标滚轮缩放（0.5x ~ 2.0x）
- **平移**：鼠标拖拽空白区域平移
- **重置**：双击地图空白区域复位至居中
- **渲染**：使用 SVG 绘制节点（圆形）+ 连线（直线），节点内显示类型图标
- **内嵌位置**：页面左侧区域（占比约 55%~60%），非弹窗/非全屏


## 第七章：战斗系统（完整时序）

### 7.1 战斗初始化
进入战斗节点时，引擎根据节点类型（普通/精英）和种子从“遭遇池”中抽取怪物组合（1~6 只）。玩家当前 HP 继承自探索状态。

### 7.2 单次逻辑步（每推进一次 `virtualTime`）

1. **触发前置钩子**（若有模组注册）。
2. **oGCD 扫描与执行**：
   - 遍历玩家和所有怪物。
   - 对每个实体的 oGCD 槽位，检查独立冷却归零、条件成立。
   - 收集所有满足条件的候选，按优先级排序，**仅执行最高优先级的一个**。
   - 执行后，将该技能的冷却值写入实体冷却映射。
3. **GCD 处理**（若本步未执行 oGCD）：
   - 若实体 `gcdCounter > 0`：`gcdCounter -= 本次推进的毫秒数`（若小于 0 则归零）。
   - 若实体 `gcdCounter === 0`：从 GCD 序列取当前技能执行，并将 `gcdCounter` 设为该技能的 `gcdCost`，推进序列指针。
4. **触发后置钩子**。
5. **统一衰减**：所有实体的 oGCD 冷却和 Buff 剩余时长减去本次推进的毫秒数（下限 0）。
6. **终止判定**：玩家或怪物方全灭，则置状态为 `finished`，记录胜者。

### 7.3 加速与暂停
- **暂停**：引擎停止推进 `virtualTime`，所有计数器冻结。
- **1x**：每帧推进 16ms。
- **4x**：每帧推进 64ms。
- **MAX**：同步循环一次性跑完所有逻辑，直达结算。

### 7.4 战斗结算
战斗结束后：
- 玩家胜 → 节点标记清理，玩家保留当前 HP，返回探索模式。
- 玩家败 → 游戏结束，弹出结算面板（记录到达层数、总伤害等）。


## 第八章：契约系统

### 8.1 设计目标
所有副作用操作（伤害、治疗、施加 Buff、消费随机数、写日志）均通过**契约函数**进行，而非直接修改 `#state`。模组作者只能调用契约，不能直接触碰私有状态。

### 8.2 核心契约清单（内置）

| 契约标识 | 输入 | 输出 | 职责 |
| :--- | :--- | :--- | :--- |
| `damage.apply` | 来源 ID、目标 ID、基础伤害、暴击修正标识 | 实际伤害、是否暴击 | 扣减目标 HP，更新总伤害统计，消费随机数判定暴击 |
| `heal.apply` | 来源 ID、目标 ID、基础治疗量 | 实际治疗量 | 恢复目标 HP（不超过上限），更新总治疗统计 |
| `state.query` | 选择器（路径或函数） | 只读数据切片 | 返回状态的深拷贝只读代理，禁止写操作 |
| `prng.next` | 无 | 0~1 之间的浮点数 | 推进 Mulberry32 状态，返回伪随机数 |
| `buff.apply` | 目标 ID、Buff ID、层数、持续毫秒数 | 无 | 在目标的 Buff 映射中新增或叠加 |
| `combat.log` | 字符串消息 | 无 | 追加至环形日志缓冲区（容量 100 条） |

### 8.3 注册与覆盖规则
- 所有契约实现在系统启动时注册至中央注册表（`Registry`）。
- 注册表采用后覆盖策略：后加载的模组提供的同名契约覆盖先加载的。
- `/mods/dev/` 路径下的模组拥有最高优先级。


## 第九章：模组系统

### 9.1 模组物理规范
每个模组是一个独立目录，必须包含：
- `manifest.js`：导出 `{ id, version, provides: Symbol[], requires: Symbol[], type }`
- `setup.js`（或 `index.js`）：导出 `setup(context) => { skills: [], monsters: [], mapGenerators: [] }`

### 9.2 加载六步法（严格顺序）
1. **发现**：Vite 的 `import.meta.glob` 扫描 `/src/mods/**/manifest.js`。
2. **依赖提取**：加载所有 manifest，构建 `requires` → `provides` 有向图。
3. **循环检测**：若存在环，抛出详细错误并终止加载。
4. **拓扑排序**：Kahn 算法排序，保证依赖先于被依赖方加载。
5. **实例化**：按序执行 `setup`，将返回的技能/怪物/地图生成器注册到全局池。
6. **覆盖裁决**：后加载覆盖先加载。`/mods/dev/` 自动排在最后。

### 9.3 热更新支持（仅开发环境）
- 模组文件变更时，引擎重新执行加载流程（保留当前 `#state` 不变）。
- 若依赖图变化，需手动刷新页面。

### 10.2 地图区交互细则
- **鼠标滚轮**：缩放地图
- **鼠标拖拽**：平移地图
- **单击节点**：若为目标节点可移动，则移动玩家至该节点；若为战斗节点且未清理，则触发战斗
- **悬停节点**：显示节点名称和类型提示
- **当前节点高亮**：玩家所在节点用亮色边框突出

### 10.3 右侧面板行为
- 探索模式下：技能序列可编辑，可拖拽调整
- 战斗模式下：地图区半透明遮罩（不可点击移动），右侧面板显示战斗进度（HP 条跳动、日志滚动）
- 战斗结束后遮罩移除，地图恢复可操作

### 10.4 种子输入框
- 默认自动填充随机种子（灰色只读状态，但可点击修改）
- 玩家修改后需确认“重置地图？”
- 旁边带“🔄”随机刷新按钮


## 第十一章：结算与本地历史

### 11.1 结算面板内容（战斗失败或通关后弹出）
- 到达层数
- 总逻辑耗时（`virtualTime` 换算为秒）
- 玩家总输出伤害 / 总治疗量
- 清理节点数 / 总访问节点数
- 使用的种子
- 技能序列摘要
- 胜负结果

### 11.2 本地存储功能（纯单机）
- **自动保存**：每层开始时自动存档（仅保存种子、层数、已清理节点列表，不保存战斗中间状态）
- **手动保存**：玩家可随时保存当前进度
- **读取存档**：从 LocalStorage 读取并恢复
- **历史记录**：保存每次通关或死亡的简要数据（供玩家回顾）
- **无排行榜**：无任何上传功能

## 第十三章：异常处理与安全防护

- **模组执行异常**：捕获同步错误，状态置为 `error`，UI 显示遮罩，不崩溃。
- **超时保护**：若 `virtualTime` 超过 300000ms（5 分钟虚拟时间）且战斗未结束，强制终止判定为失败。
- **内存保护**：每次重置切断旧状态引用，日志环形缓冲区固定容量。
- **地图生成安全**：若生成算法陷入死循环（极少情况），内置步数上限（10000 步）强制退出并报错。
