## 一、这个项目是什么

纯文字、模组驱动、**确定性**的 Roguelike 自动战斗工具。

玩家不操作战斗。玩家做的事是：**编排技能序列**（GCD 循环队列 + oGCD 优先级槽），然后让角色自动打，观察结果，回去改序列。战斗过程是纯函数：给定 `(seed, 序列配置, 内容模组)`，逐帧结果必然一致，1x / 4x / MAX 三种倍速下的最终状态**逐字节相同**。

技术栈：原生 JS（ESM，无框架）+ Vite + Vitest + Howler（音频，可选）。无 TypeScript，用 JSDoc 标注类型。UI 是手写 DOM + 模板字符串，地图用 SVG。

**为什么强调确定性**：这是整个项目的立项卖点。种子是复现整局的完整凭据。所有涉及随机、时间、浮点的改动都必须先想清楚是否破坏这一点 —— 见「五、不可违反的内核不变量」，其中一条现在有测试守着了（`app-wiring.test.js` 的「渲染再多也不消费随机流」指纹对拍）。

## 五、不可违反的内核不变量

改代码前必须理解这六条。违反其中任何一条，确定性就崩了，而且**测试不一定立刻报错**（会在别的种子、别的倍速下才暴露）。

### 1. 三流随机分派

`prng.js` 用 `deriveSeed(masterSeed, streamName)` 把主种子派生成互不干扰的独立流：

- **map 流** —— 地图生成
- **battle 流** —— 战斗内随机（暴击、随机目标、随机 Buff）
- **player 流** —— 玩家开局 seedBonus

**规则**：绝不跨流借随机数，绝不在流内插入或删除一次 `next()` 调用而不评估影响。战斗流的调用次数必须与倍速无关。UI 想要随机数（比如打乱展示顺序），用 `Math.random()`，不要碰 PRNG 流。

UI 层新增了两条守门测试：开局走种子对话框不消费任何流；战斗屏渲染 50 次后的终态指纹与安静跑完全一致。

### 2. 绝对到期时间戳

冷却与 Buff 存的是**绝对到期虚拟时刻**（`readyAt`、`expiresAt`），不是剩余时间。

**为什么**：剩余时间需要每帧递减，递减次数依赖帧数，帧数依赖倍速 → 倍速会改变结果。绝对时间戳只需比较 `virtualTime >= readyAt`，与推进步长无关。

**规则**：任何新增的计时字段都必须用绝对时间戳，不许写「剩余 N 毫秒」。

### 3. 时间量必须是 STEP_MS 整数倍

所有技能施法时间、冷却、Buff 持续都必须对齐到 `STEP_MS`（16ms）。模组加载时的 `normalize` 会强制这一点，`tests/unit/mod-loading.test.js` 有对应断言。

**规则**：新增内容时别写 `cooldown: 2500`，先确认能被 `STEP_MS` 整除。

### 4. 属性单一数据源

玩家的 `maxHp / attack / defense / critChance` **从不手写**，一律由
`(exp, equipment, seedBonus, permanentBonus)` 经 `recalcPlayer` 重算。存档只存
`exp`、装备、当前 `hp`、`permanentBonus`。调用时机：升级、穿脱装备、强化、
读档、商店消费、事件结算。

上一版这条被商店与事件违反了（花 40 碎片买的「磐石之核」一次重算后归零）。
**现已修复并有三道防线**：

1. 内容只允许走 `addPermanentBonus(player, {...})`（`derived.js`）
2. `GameFlow.purchase` / `resolveEvent` 在 `apply` 后统一 `recalcPlayer`
3. `tests/unit/mod-loading.test.js` 有个守卫测试，扫全部官方商品/事件的
   `apply` 源码，出现 `state.player.maxHp = …` 之类赋值就直接红灯

**要加新的永久成长属性时**：只改 `PERMANENT_BONUS_FIELDS` 一处。

### 5. 音频永不影响逻辑

`AUDIO_PLAY` 契约返回 `undefined`、不消费随机数、sink 抛错不向上传播、sink 为 `null` 时静默丢弃。`tests/unit/contracts.test.js` 有四条测试锁定这个行为。

**规则**：不要让音频调用出现在会影响状态的表达式里。

### 6. UI 不得触碰活状态（本轮新增）

`store.unsafeGetState()` 返回的是**可写的内部状态对象**，只给 core 与测试用。
装配层的唯一取数入口是订阅回调缓存的快照：`main.js` 里 `store.subscribe(snap => { latest = snap; renderAll(); })`，所有屏幕通过 `getSnapshot()` / `getState()` 拿它。

**为什么**：一是防误写（快照深冻结），二是省掉重复克隆 —— 每帧只克隆一次，
屏幕再多也不会翻倍。历史上有个真实坑：`descend()` 用 `unsafeGetState()` 拿到的
活对象读 `floorNumber`，`enterFloor` 就地改完之后才 return，于是「下第 1 层」
返回了 `floorNumber: 3`。

**规则**：屏幕不许自己调 `store.update`，一律走 `GameFlow` 方法；
装配层要改状态（例如测试里强制战败清空序列）必须显式注释说明。

### 平局打破规则

oGCD 候选排序是 `(槽位优先级降序 → 技能自带优先级降序 → skillId 字典序)`。字典序那一档是**必须的**：没有它，同优先级技能的执行顺序会依赖 `Map` 迭代顺序。

oGCD 抢占作用域是「每实体每步至多一个」，**不是全局一个**。

### 通关是怎么实现的（P1-6，接手前先读这段）

**决策**：终点 = 第 50 层（`VICTORY_FLOOR`），通关后可选无尽，经验曲线与
`SKILL_UNLOCK_MAX_LEVEL` 本轮**不动**。

- **触发点**：`GameFlow.descend()` 里判 `floorNumber >= VICTORY_FLOOR && !victoryAchieved`
  → 走 `#settleVictory()` 而不是生成第 51 层。写 `status=FINISHED` +
  `winner=PLAYER` + `battleEndReason='victory'` + `floorsCleared++`，
  `appendHistory({outcome:'victory'})`，并**清掉自动槽**（留着会让「继续游戏」把玩家
  放回一个已通关、再点出口什么都不发生的节点）。
- **继续无尽**：`GameFlow.continueEndless()` 把状态放回 EXPLORING、清 winner，
  `victoryAchieved` 保持 true ⇒ 之后每次下层都是普通下层，永不再结算。
  无尽段死亡另记一条 `outcome:'death'` + `victoryAchieved:true`，战绩屏标
  「通关后 · 无尽」，不冒充第二次通关。
- **状态与存档**：新增 `state.victoryAchieved`，随 `serializeRun` 入档，
  `summarizeSave` 带出来（存档屏打「已通关」标签）。**老存档缺字段按 false 处理，
  没升 schema 版本** —— 理由同 `permanentBonus`：纯增量、默认值语义正确。
  不带这个标记的话，从第 51 层读档再下层会补触发一次通关。
- **一个必须记住的守卫**：通关结算也把状态写成 `FINISHED + winner=PLAYER`，
  所以 `finishBattle()` 现在会先检查 `activeBattle === null` 并返回
  `{settled:false}`。少了这道守卫，rAF 循环会在通关后再调一次结算并踩空。
- **UI**：终点层的出口按钮改成「踏入轮回尽头（第 50 层通关）」；
  `dialog.openSummary` 现在支持 `secondaryLabel/onSecondary`，并且**结算面板的按钮
  不再走 `onClose`** —— 两个出路时 `onClose` 会把玩家没选的那条也执行一遍。
- **深度的尽头**：官方遭遇模板 `maxFloor: 999`。`pickEncounter` 现在在本层无货时
  回退到「minFloor 不超过本层的最深一档」（仍是纯函数，不消费随机数），
  所以第 1200 层也不会把一局好局打死；代价是 999 层以上难度不再爬升。

#### 本轮实现里值得知道的三个取舍

1. **解锁校验放在 `GameFlow` 而不是 `scheduler`。** `GameFlow` 构造时就
   `buildUnlockTable(pool.skills)` 并对外暴露 `flow.unlockTable`（屏幕共用同一张，
   `main.js` 不再自己建）。清洗点在 `startBattle()` 与 `restoreRun()` 两处，
   **剔除而不是报错** —— 报错会让玩家卡在"打不了仗"。等级取
   `levelFromTotalExp(exp)` 而非 `player.level`：读档时后者还是旧值，要等
   `recalcPlayer` 才更新。`scheduler` 里没有查表，每步零额外开销。
2. **暂停 = 停止推进虚拟时间**，且 `GAME_STATUS.PAUSED` 现在真的会出现在状态里。
   连带两个必要修正：战斗屏速度按钮在暂停态必须仍可点（否则按下 ⏸ 就再也开不回来）；
   暂停中不给手动存档入口 —— 因为 `GameFlow` 的结算/读档路径会把状态写成 `EXPLORING`，
   暂停中的战斗存进去就恢复不出来（这是个真陷阱，已写成测试）。
   `restoreRun` 里的序列清洗特意放在 `log = []` 之后，否则通知会被自己抹掉。
3. **`logLimit` 只裁剪展示数组**（`battleScreen` / `mapScreen` 收一个 `getLogLimit`），
   `state.log` 容量仍固定 `LOG_CAPACITY`。有一条测试直接拿这个当确定性证明：
   同一场战斗在 100 / 50 两档设置下 **battleFingerprint 必须逐项相等**。
   重绘缓存的键也从"长度"改成 `长度*1000+limit`，否则改设置后条数没变就永远不重绘。

### 模组分发与沙箱：已决策，未实施（接手必读，别重新推导）

**要解决的问题**：产品要求"玩家一键加载别人的 mod"，而本项目只挂 GitHub Pages
（无后端）。但 mod 是**构建期打包**的（实测：`dist/assets/setup-*.js` 里能 grep 到
技能名），所以今天唯一的安装方式是 fork + 自己 build。

**决策链（每一步都被事实推翻过一次，记下来避免重走）**：

| 提案 | 结论 | 为什么 |
|---|---|---|
| 只支持 fork + 自己 build | ❌ 否 | "玩家是来玩的，不是来当极客自己构建游戏的" |
| JSON 数据包 + 固定效果词汇表 | ❌ 否 | 违反计划书第 27 行（模组要能造新机制） |
| zip / modpack 容器 | ❌ 撤回 | 不需要音频与图片素材，zip 唯一存在理由不成立；单个自包含 `.js` 是更好的分发单元（可读、可 diff、可 hash） |
| SES / Compartment 同 realm 沙箱 | ❌ 否 | 改动最小且保住同步 execute，但**无法计量** —— 一个 `while(true)` 就冻住页面 |
| 整个战斗模拟搬进不透明源 iframe+Worker | ⏸ 备用 | 隔离最强、能 terminate，但边界重构量最大；列为性能不过关时的退路 |
| **QuickJS-WASM 跑 mod 代码** | ✅ **采用** | 真计量（`shouldInterrupt`）+ 内存上限 + 默认无能力；作者写的还是 JS |

**关键洞察（为什么不必降级成 JSON）**：新机制只需要一个新的 `execute` 闭包，不需要改
core —— 官方工厂产出的对象与模组手写 `execute` 产出的是同一种东西。只要沙箱能跑 JS，
计划书的全部承诺都能保留。

**测量依据**（`node tools/mod-shape-report.mjs` 可重跑）：技能 90/90（100%）由 4 个工厂
模板生成、手写 0；条件 6 种谓词形状；商品+事件 11 种状态操作；怪物/遭遇/Buff 全纯数据。
这组数字证明"JSON 能覆盖今天的全部内容"—— 但也**仅止于此**，那正是它被否的原因。

**一个顺手的好处**：计划书第 253 行早就写了"模组作者只能调用契约，不能直接触碰私有
状态"。沙箱不是加限制，是把这条已有纪律从"靠 lint 和自觉"变成物理事实。

**进度**：S1（内容指纹 + 存档命名空间）、S1.5（`fate-shim`）、S0（POC，`npm run mod:poc`）、
**S2（沙箱加载路径）均已完成** —— 第三方包现在真能给游戏注入机制。
**待办**：S4 modindex（URL 一键安装）→ S5 改计划书 3.2。能力面（S2b）已完成。
当前沙箱只开放 `family/skill/buff/monster/encounter` 五类注册；`shopItem/event/mapGenerator`
**显式报错**而不是静默丢（事件的 `apply` 是每个选择项各带一个函数，跨界签名要单独设计）。
→ S3 模组管理界面 → S4 `modindex.json` + URL 加载 → S5 修订计划书 3.2"第三方与官方
加载机制无任何区别"→ 两层机制（**那句话正是安全问题的来源**）。

#### S1.5 落地时抓到的两个真 bug（值得记住，因为它们都是"设计文档里看不出来的"）

1. **shim 的注册缓冲是全局单份且 drain 即清空** ⇒ 同一个包被加载第二次拿到空内容；
   两个包共用 shim 会互相吞注册。改成按包 id 分作用域 + drain 返回副本。
2. **示例包的 `void.ruin` 从一开始就是坏的**：它写 `ctx.query('monsters.' + id + '.hp')`，

   永远 `undefined` ⇒ 技能安静地按"0 层"分支跑。这类"看上去生效其实没生效"最难查。
   修法不是去修路径解析（点分路径与含点 id 天生冲突），而是给一等 API：
   `ctx.entity(id)` / `ctx.buffStacks(entity, buffId)` / `ctx.hasBuff(...)`。
   **这条限制写进了 fate-shim 注释与开发指南，S2 抄进沙箱文档时必须带上。**

设计文档 §10 还列了 **8 条离线环境无法验证的待办**（Release 资产 CORS、Pages 能否设
CSP、QuickJS 的 ES2020 语法面、wasm 体积与许可证…），接手第一件事建议先看那份。

2. **Store 订阅重入无正式方案**：listener 里调 `update` 目前只靠装配层 `renderDepth`
   限深挡一下，不是根治。
3. **jsdom 无布局**：焦点陷阱那条只断言了 `defaultPrevented`，没断言"焦点真的被拉回
   最后一个元素"。真浏览器体检覆盖了大部分，但它不在 CI 里。
4. **测试耗时**：`app-wiring` 6.6s、`screens` 1.4s，慢在 MAX 整场战斗与 300 怪物图鉴。
   嫌慢可把图鉴计数类断言改成抽样。

### UI 的视觉自检：`npm run ui:audit`

CSS 是闭眼写的（jsdom 没有布局引擎），所以仓库里带了一个真浏览器体检工具：
`tools/ui-audit/`（`run.mjs` 起 dev server + 驱动无头 Edge/Chrome，`harness.js`
把应用开到每个界面并量 DOM，结果以 JSON 回传）。

```bash
npm run ui:audit                                      # 13 界面 × 1440x900
npm run ui:audit -- --views=1440x900,900x900,420x900  # 视口矩阵
npm run ui:audit -- --only=map,victory --shots=.ui-audit
```

量的项：横向溢出、零高度可见元素、元素跑出视口、文本被裁且没写 ellipsis、
面板中心被遮挡、对比度 < 4.5:1、当前屏几乎是空的，外加屏高占比 / 节点数 /
雾点数 / 可达节点 / 实体卡数 / 列表行数等指标。

**六个血泪约束**（改这个工具前先读，每一条都是先踩过才写下的）：

1. **每个用例都有前置断言**。第一版没有，`victory` 用例其实在第 50 层路上被怪打死，
   量的是"阵亡后的地图"，却报 ✓ —— 比没有体检更坏，因为它给人虚假的安全感。
   现在 `PRECONDITIONS` 会先确认"通关面板真的打开了"，不满足就直接判定不可信。
2. **SVG 内部的几何盒不算溢出**。外层 `<svg>` 会裁掉画布外的内容，放大后的
   `.map-viewport` 超出视口是正常的，别照着它去"修"（已经踩过一次）。同时
   `.map-svg { overflow: hidden }` 写成显式规则，不依赖 UA 默认值。
3. **脚手架造的状态必须可达**。第一版用改 `currentNodeId` 传送，结果周围全是雾，
   量出 `reachable=0` 被误判成缺陷。现在 `walkTo()` 真的沿邻接表走过去（撞到战斗
   就地打完），只有 `victory` 例外并注明原因（50 层的怪会当场打死体检角色）。

4. **浏览器本身也会坑你：坏掉的浏览器不能算成"界面有问题"**。实测踩过：Edge 后台
   自升级后卡着十几个旧版本僵尸进程，新启动的实例全部把命令行交给它们然后秒退（
   `--dump-dom` 输出 0 字节），而体检把每个组合都读成"零节点、布局塔了"—— 假报 13 个问题。
   现在 `run.mjs` 先用 `--version` 探一次，跑不起来就**退出码 3 并说明真正原因**。
   排障要点：`Get-CimInstance Win32_Process -Filter "Name='msedge.exe'"` 看进程
   路径是不是混着多个版本号（混版 = 必崩）；`Application\` 下只剩一个版本目
   录就好。另注：Windows 版 `msedge --version` **本来就不输出**（那是 Linux 习惯），
   拿它当"浏览器死了"的证据会误判 —— 预检所以下面要跟一条真实渲染探测。

顺带：无头浏览器要 `--user-data-dir` 指到临时目录、`--screenshot` 必须给**绝对路径**
（相对路径会"报告说写了、目录其实空的"），首屏前要先**预热**一次让 vite 编译完依赖图，
否则第一个界面几乎必然超时误报。

5. **每个浏览器实例必须用自己的 `--user-data-dir`**。全量 14 组合里有 3 个报
   "有问题"、单独 `--only=` 又全过 —— 真因是工具自己：所有实例共用一个 profile，
   上一个还在收尾（helper 进程抢着放锁），新实例就把命令行交给前者然后自己退出
   （0 输出），于是被算成布局问题。现在 `newProfileDir()` 每组合一个，跑完只删
   自己建的目录；**零输出走退出码 3 报"环境问题"**，不冒充"UI 有问题"。
6. **量异步渲染的屏之前必须 `await screen.render()`，不能用 setTimeout 等**。
   体检跑在 `--virtual-time-budget` 下，3 秒**虚拟**时间只对应几毫秒真实时间，
   而 IndexedDB 读的是**真实时钟** —— 轮询永远等不到，量到的是空骶架（假报零高度）。

## 7.6 CSS 类必须真的有规则（`css-classes.test.js`）

排版塔了不报错、不变红，只会用默认样式安静地渲染 —— 所以本轮加了反向守卫：
**JS/HTML 里写出来的每个 class，styles.css 里必须有规则**，否则测试红。
当场拓出 5 个漏写的类（`.menu-prev` / `.transfer-bar` / `.seed-fingerprint` 等）。

两个约：① 带 `${}` 插值的 class 属性会被先剔成哨再扫（不然动态行整个扫不到，
而动态行恰恰最多），含哨兵的 token 丢弃（`q${n}` 剩下的 `q` 不是类名）；
② 确实不需要样式的修饰类进 `ALLOWLIST` 并写明原因，不要直接关掉测试。

一条经验：**改引擎时务必保持 `cross-speed.test.js` 绿，改装配时务必保持
`app-wiring.test.js` 里那条指纹对拍绿** —— 后者是唯一能自动发现「UI 改动破坏了
确定性」的手段。
