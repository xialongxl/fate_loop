# 开发两轮审查流程

从本阶段开始，任何战斗、数据、UI 或运行时改动都必须经过两轮审查。两轮审查的目标不同，不能用一次构建成功替代。

## 第一轮：冒烟审查

命令：

```bash
npm run review:round1
```

覆盖范围：

- 所有 JSON 内容能够被 Vite/AJV 加载和校验。
- 跨文件 ID 引用有效。
- 技能序列只调度防御、霜爆和能量专注等主动技能，基础射击由独立自动攻击时钟驱动。
- 能量低于 35 时，能量专注应在普通技能之前获得执行机会。
- 基础射击不应改变技能序列的最近技能状态。
- Boss、敌方弹幕和玩家自动攻击能够生成。
- 竞技场没有立即进入异常结束状态。

第一轮失败时，不进入内容平衡或视觉验收。

## 第二轮：完整审查

命令：

```bash
npm run review:round2
```

覆盖范围：

- 全量 Vitest 单元和集成测试。
- 条件、技能、技能序列、Boss 阶段、移动、对象池、空间哈希和重开流程。
- 生产构建。
- 数据 Schema 与跨引用检查。

## 合并前人工验收

自动化通过后，还要在开发服务器中检查：

- Boss 名称和血条固定在竞技场顶部中央，不随 Boss 横向移动。
- 玩家真实判定点清晰可见。
- 玩家弹幕与敌方弹幕颜色和形态明显区分。
- 擦弹、Shift 专注减速、Z 手动攻击和自动攻击有效。
- `P` 可以手动暂停和恢复，暂停时弹幕、Boss、玩家和技能冷却都不推进。
- 窗口失焦或标签页隐藏后自动暂停，恢复窗口后必须按 `P` 继续。
- 霜爆演出出现在 Boss 受击位置，并出现伤害数字。
- 玩家死亡后显示结束状态，按 R 可以重开。
- 桌面端和窄屏布局没有关键 UI 遮挡。

完整命令：

```bash
npm run review
```

后续新增功能应同时补充对应的自动化测试和人工验收项，不能只修改功能代码。
