# 技术实施细化方案

**依据**：《命运轮回：FATE LOOP》完整设计计划书（主规格）
**作用**：把主规格中的设计意图落成可直接编码的目录结构、接口签名与契约定义。本文与主规格冲突时，以主规格的设计意图为准、以本文的技术形式为准。
**状态**：设计已定稿（含 8 项技术裁决 + 3 项玩法决定），尚未开始实现

### 技术栈修正（沿用旧计划书两项选型）

主规格第二章的持久化选型为 LocalStorage、且未列音频层。经确认，这两项沿用旧计划书：

| 层级 | 选型 | 版本约束 | 说明 |
| :--- | :--- | :--- | :--- |
| 数据持久化 | IndexedDB（主）+ LocalStorage（降级） | 浏览器内置 | 取代主规格 11.2 的纯 LocalStorage；仍无网络请求，不违反 3.4 |
| 音频 | Howler.js | 2.2.x（锁定） | 主规格未定义音频，此处补充 |

Howler 是本项目唯一的运行时第三方依赖。它不参与任何确定性路径（见裁决 8），因此不影响 3.3 铁律。

## 1. 对主规格的八项技术裁决

以下裁决用于消除主规格中的规格歧义，不改变任何玩法设计。

### 裁决 1：时间统一为"绝对到期时间戳"

主规格 4.4 使用 `lastCastTime` 比较，5.2 使用 `gcdCounter` 倒计时递减。两套并存会在步长非整除时产生分歧。

**统一为**：所有冷却类字段一律存"到期时的 virtualTime"，只比较、不递减。

| 废弃字段 | 替代字段 | 判定式 |
| :--- | :--- | :--- |
| `gcdCounter` | `gcdReadyAtMs` | `virtualTime >= gcdReadyAtMs` |
| `ogcdCooldowns`（剩余值） | `ogcdReadyAtMs`（到期值） | `virtualTime >= readyAt` |
| `buffs[].remainingMs` | `buffs[].expiresAtMs` | `virtualTime < expiresAtMs` 视为在场 |

收益：无累减误差、无"归零判等"陷阱、MAX 模式与 1x 模式结果逐位一致、Buff 衰减不再需要每步遍历（改为惰性判定 + 定期清理）。

### 裁决 2：PRNG 按用途分流，战斗流按节点派生

主规格 5.1 只有单个 `prngState`。玩家往返探索会改变随机数消费顺序，导致同种子下怪物配置漂移，违背 3.3。

**分流方案**（子种子派生为纯函数，不含状态）：

| 流 | 派生输入 | 用途 |
| :--- | :--- | :--- |
| 地图流 | `(seed, floorNumber)` | 网格尺寸、节点延伸、类型分配、出口选取 |
| 遭遇流 | `(seed, floorNumber, nodeId)` | 该节点抽取哪个遭遇模板、怪物属性浮动 |
| 战斗流 | `(seed, floorNumber, nodeId, attemptIndex)` | 战斗内暴击判定、randomEnemy 选取 |

`attemptIndex` 恒为 0（战斗只能打一次，赢则清理、输则终局），保留该维度是为将来可能的"重试"扩展留出接口，不影响当前确定性。

派生函数：`deriveSeed(baseSeed, ...parts) -> uint32`，对各部分做 FNV-1a 哈希混合。地图流与遭遇流互不干扰，因此探索顺序不再影响任何生成结果。

### 裁决 3：oGCD 抢占的作用域为"每实体每步至多一个"

主规格 7.2 步骤 2 的措辞在"遍历所有实体"语境下可被读作全局一个。明确为：

- 对每个实体独立收集其就绪 oGCD 候选，按 `priority` 降序、`skillId` 字典序（打破平局，保证确定性）取第一个执行。
- 实体执行 oGCD 后，本步不再为该实体推进 GCD；其他实体不受影响。

### 裁决 4：技能数据分 authoring 与 runtime 两种形态

主规格 4.2 要求模组作者写秒，5.3 表格写整数毫秒。二者是同一份数据的两个阶段。

- **authoring**（模组文件内书写）：`{ gcdCost: 2.5, cooldown: 60 }`，单位秒，允许小数。
- **runtime**（加载器 normalize 后）：`{ gcdCostMs: 2500, cooldownMs: 60000 }`，整数毫秒，冻结。

normalize 阶段同时校验：毫秒值必须为正整数且为 `STEP_MS`(16) 的整数倍，否则加载报错。这条硬约束让"步长推进"与"到期比较"永远等价，是确定性的根基。

### 裁决 5：确定性状态与视图状态分离

`mapOffsetX / mapOffsetY / mapZoom` 从 `#state` 移出，独立为 `viewState`（不入存档、不入快照哈希）。`#state` 的任意两次快照只要种子与操作序列相同就必须逐字段相等，这是阶段 1 单测的断言基础。

### 裁决 6：集合类字段的序列化形态

`visitedNodeIds / clearedNodeIds` 运行时为 `Set<string>`，存档时转为已排序数组（排序保证存档字节稳定），读档时还原为 Set。`buffs / ogcdReadyAtMs` 运行时为 `Map`，存档时转为按键排序的二元组数组。

### 裁决 7：存储层为三适配器 + 同步写队列

IndexedDB 是异步 API，而战斗与生成逻辑全部禁止 async（ESLint 硬约束）。两者必须隔离。

**接口（三个适配器同形）**：

```js
/** @typedef {{ get(key):Promise<any>, set(key,value):Promise<void>,
 *              delete(key):Promise<void>, keys():Promise<string[]>,
 *              isAvailable():Promise<boolean> }} StorageAdapter */
```

| 适配器 | 文件 | 用途 |
| :--- | :--- | :--- |
| `IndexedDbAdapter` | `persistence/adapters/indexedDb.js` | 主用。库名 `fate-loop`，store：`saves` / `history` / `settings` |
| `LocalStorageAdapter` | `persistence/adapters/localStorage.js` | IndexedDB 不可用时降级（隐私模式、配额耗尽、旧浏览器），前缀 `fate-loop:` |
| `MemoryAdapter` | `persistence/adapters/memory.js` | 单测与 Node 环境，无副作用 |

选择时机：启动时 `await pickAdapter()` 探测一次并缓存结果；降级时在 UI 展示一条提示（存档仅保留在本浏览器，可能被清理）。

**同步逻辑如何存档**：`core/**` 永不直接调存储。`SaveService` 订阅 Store 变更，在存档点（每层开始、手动保存、Run 结束）将快照推入写队列，队列在宏任务中串行 flush。同一 key 的待写项只保留最新一份（合写）。写入失败不影响游戏进行，仅记日志并提示。

**存档内容**（与主规格 11.2 一致，不存战斗中间态）：`{ schemaVersion, seed, floorNumber, currentNodeId, visitedNodeIds[], clearedNodeIds[], playerHp, gcdSequence[], ogcdSlots[], metadata }`。带 `schemaVersion` 以便后续迁移；版本不匹配时拒读并提示，不做静默丢弃。

### 裁决 8：音频为契约，且与确定性完全隔离

范围：**UI 反馈音效 + 战斗事件音效**，本期不做 BGM（目录预留位置，不写实现）。

新增第 7 个契约 `audio.play`，理由：放音是副作用，按 8.1 必须走契约；模组作者希望为自定义技能配音时也只能调契约；无头环境（Vitest）只需注入 no-op 实现。

**与确定性的隔离规则（强约束）**：

1. `audio.play` 返回 `void`，不报告成败，调用方无法从它获取任何信息——因此它不可能影响战斗分支。
2. 它不消费随机数、不读 `virtualTime` 以外的状态、不写 `#state`。
3. 内部完全不报错：音频初始化失败、资源缺失、浏览器自动播放策略拦截，均静默降级为无声。
4. 去掉整个音频模块后，确定性单测必须仍全红（这是一条可执行的验收项）。

**速度模式联动**：

| 模式 | 行为 |
| :--- | :--- |
| 1x | 全部事件音效正常播放 |
| 4x | 正常播放，由节流阀限制密度 |
| MAX | **全程静音**，仅在结算时放一个胜 / 败音 |
| 暂停 | 停止新声音，不中断已在放的 |

MAX 模式在几十毫秒内可能产生上千次伤害事件，逐事件放音会直接卡死音频线程，因此静音是硬规则而非优化项。

**节流阀**：同一 `soundId` 在 50ms 窗口内去重；全局并发上限 8 路，超出时丢弃新声音（不打断旧声音）。去重窗口基于物理时针（`performance.now()`），这是允许的，因为它只位于 `ui/audio/**` 且不参与逻辑。

## 2. 已定的两项设计缺口

主规格未定义、已经你确认的玩法决定：

### 决定 A：经济为“命运碎片”

| 项 | 规则 |
| :--- | :--- |
| 货币名 | 命运碎片（`fateShards`） |
| 获取 | 战斗胜利掉落；普通节点基础量，精英节点双倍 |
| 休息节点 | 恢复最大 HP 的 30%（向下取整），使用一次后失效 |
| 商店节点 | 提供 3 个待售项（由遇流 PRNG 按 nodeId 抽取，同种子同节点商品固定）：新技能 / 属性强化 / 一次性回复 |

商品与掉落量均为模组注册的数据，引擎不硬编码任何商品（遵 3.1）。`fateShards` 入 `#state` 与存档，参与确定性断言。

### 决定 B：剩余 15% 为 `empty` 空地

节点类型完整分配（排除起点与死路后，合计 100%）：

| 类型 | 占比 |
| :--- | :--- |
| `combat` 普通战斗 | 45% |
| `elite` 精英战斗 | 12% |
| `rest` 休息 | 12% |
| `shop` 商店 | 8% |
| `event` 事件 | 8% |
| `empty` 空地 | 15% |
| `exit` 出口 | 固定 1 个（不入比例分配） |

`empty` 与 `deadEnd` 的区别：空地仍连通主通路、可通行，只是无事件；死路不可通行。

### 决定 C：oGCD 条件不可编辑

5.2 的 `ogcdSlots` 含 `condition` 谓词。谓词是函数，无法在纯文字 UI 中安全编辑。条件由技能定义自带（模组作者书写），玩家只能选择“放哪个技能进槽位”与“槽位优先级”。旧计划书的可视化条件编辑不纳入本期。

```js

  // context: { registry, contracts:{...symbols}, log, defineSkill, defineMonster }
```

加载器对 `setup` 返回值执行 normalize（裁决 4）后写入全局池；任一模组抛错则整体加载失败并将状态置 `error`，不做部分加载。

## 7. ESLint 硬约束

```js
// eslint.config.js 关键规则
'no-restricted-properties': [error,
  { object: 'Math',        property: 'random', message: '使用 prng 契约' },
  { object: 'Date',        property: 'now',    message: '仅 core/prng.js#randomSeed 可用' },
  { object: 'performance', property: 'now',    message: '战斗逻辑禁止物理时钟' },
],
'no-restricted-syntax': [error,
  { selector: 'AwaitExpression',            message: '战斗与生成逻辑必须同步' },
  { selector: 'FunctionDeclaration[async=true]' },
  { selector: 'NewExpression[callee.name="Date"]' },
],
```
`core/prng.js` 与 `ui/**` 通过 overrides 局部放宽 `Date.now`；`ui/audio/**` 额外放宽 `performance.now`（去重窗口专用）；`persistence/**` 放宽 `AwaitExpression` 与 async（IndexedDB 必需）。`core/**`、`contracts/**`（除 audio 适配部分）、`mods/**` 一律不放宽。

## 10. 交付顺序与验收门

不使用工时估算。阶段划分只表达**依赖顺序**与**验收门**：上一阶段的验收项全部通过才进入下一阶段，可并行项不强制串行。

| 阶段 | 依赖 | 验收门（全部可自动化） |
| :--- | :--- | :--- |
| 0 骨架 | — | `npm run dev` 无报错；`lint` 通过；故意写 `Math.random()` 必须 lint 失败 |

| 4 模组加载器 | 2 | A 依赖 B 时拓扑序正确；环依赖报错并终止；`mods/dev` 排最后；normalize 非 16 倍数时报错 |
