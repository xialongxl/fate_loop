# 模组开发指南

《命运轮回：FATE LOOP》的内容**全部**是模组。官方那 90 技能 / 300 怪物 / 100 遭遇
就跑在 `src/mods/official/` 下，和你写的东西走同一套加载器、同一套校验。
没有"官方特权 API"这回事。

仓库里有一个**会被真正加载**的示例模组：[`src/mods/dev/example-pack/`](../src/mods/dev/example-pack/)。
它是这份文档的可执行版本 —— 改坏了启动就会报错，所以它不会悄悄过期。

---

## 先分清两种写法

本项目有**两层模组**，写法不同、能力不同。想知道该抄哪个：看你要不要被别人当第三方包装进游戏。

| | 可信层（官方 / 开发者） | 第三方包（玩家装） |
|---|---|---|
| 放哪 | `src/mods/<作者>/<包名>/`，构建期打包 | 一个目录压成 zip，运行时加载 |
| 清单 | `manifest.js`（导出对象） | `manifest.json`（指定 entry） |
| 入口 | `export function setup(context) { return {…} }` | `index.js` 里 `import 'fate'` 命令式注册 |
| 能 import | core 任何东西 | **只有 `'fate'` 与包内相对路径** |
| 能做什么 | 一切（含注册契约实现、换地图生成器） | 当前：技能 / Buff / 怪物 / 遭遇 / 流派（商品与事件待开放） |
| 谁在用 | `src/mods/official/*` | `src/mods/dev/example-pack/` 就是这种写法 |

`src/mods/dev/example-pack/` 是**同一个目录两条路都能走**的样板：它按第三方写法只
`import 'fate'`，另配一个 3 行 `setup.js` 适配器给构建期加载器用。所以放进仓库就能
`npm run dev` 直接调，压成 zip 就能被玩家装。

它演示的是 S2b 之后的**全能力面**：流派 / Buff / 6 个技能 / 2 种怪物 / 3 个遭遇 /
2 件商品 / 1 个事件（`choices[].apply`）/ 一个地图生成器 / 一个 `onBattleStart` 钩子。
其中 `void.debt`（血债）是**带记忆的机制**：模块级 `Map` 记住目标上次的血量，
入口 `index.js` 里挂 `onBattleStart(() => lastSeenHp.clear())` 把单场可复现拿回来。
两条路径由 `tests/integration/example-pack-in-sandbox.test.js` 对拍 —— 同一份源码
真的送进沙箱跑一遍，与原生加载逐项比数量。

> `'fate'` 在构建期由 vite alias 解析到 `src/mods/fate-shim.js`，在沙箱里由宿主注入
> 同名模块。两边键集合必须一致，由 `tests/unit/fate-api.test.js` 守住。

### 沙箱收什么（S2b 之后：全开）

| 能力 | 构建期可信模组 | 玩家装的第三方包 |
|---|---|---|
| `family / skill / buff / monster / encounter` | ✅ | ✅ |
| `shopItem / event`（含 `choices[].apply`） | ✅ | ✅ |
| `mapGenerator` | ✅ | ✅（但要过**准入校验**，见下） |
| `onBattleStart(fn)` 钩子 | —（官方直接走 engine） | ✅ |
| 技能 `execute` / `condition` | ✅ 直接改实体 | ✅ 但只能走 `ctx.damage/heal/applyBuff/...` |
| 商品/事件 `apply(state, ops)` | ✅ 直接改 `state` | ✅ 但只能走 `ops.*`（见下） |

**为什么包不能直接改 `state`**：官方商品写的是 `state.player.hp = ...`（活对象），
而包拿到的是 **JSON 快照**。递快照而不是活对象是有意的（包不该能绕过规则改任意
字段），但"写了没反应"是最难查的 bug，所以**快照在 VM 里是深冻的**：写它会立刻抛
`TypeError` → 宿主接住 → 摘包 → 给玩家一条提示。也就是说：**照官方示例直接改
state 的包会当场报错，而不是安静地什么也没做**。

可用 ops（与官方内部同一套原语）：`permanentBonus` · `shards`（只读）·
`gainShards` · `spendShards`（返回布尔）· `setShards` · `healRatio` ·
`hpCostRatio` · `fullHeal` · `addMetadata`。不在表里的操作根本不存在 ——
包改不了序列、等级、地图这类它本就该改不了的东西。

跨界只传 **JSON 快照**；要产生效果必须走 `ctx` / `ops`，而那些操作走的正是官方
内容用的同一条 registry 路径。另有四条硬预算：
**执行 120ms / 加载 400ms / 栈 256KB / 内存 8MB（每包）**。超了就摘包：该包后续
函数空转，并给玩家一条提示 —— **不会把整局弄崩**。

### 地图生成器的准入校验（包换地图必读）

地图坏了，玩家会卡在**已经写进存档**的那一局里；而包代码不过 lint 也不过测试，
所以**装包那一刻**会把你的 `generate` 跑 5 组 (seed, floor) 采样，每组跑两遍：

1. **两遍必须逐字节相同** ⇒ 抓 `Math.random` / `Date.now`。沙箱不禁这两个，但
   非确定性的生成器会直接毁掉"同种子必得同结果"，所以这里会拒
2. **结构不变量**：节点 id 唯一、`type` 合法、start/exit 存在且不同、邻接不指向
   未知节点、起点可达出口、**可通行节点**无孤岛

两个容易踩空的细节：
- **单向邻接是合法的**，而且死路就靠它表达（死路列出邻居为了画连线，邻居不列它，
  于是 `areAdjacent` 天然拒绝走进去）。别去补反向边
- 只要求**可通行节点**全连通；死路不在可达集里是设计使然

不通过的后果：该包被拒（模组屏会写原因），**官方地图原样保留**，其它包不受影响。


## 第三方包能做到什么机制（实测，不是承诺）

`tests/integration/sandbox-mechanics.test.js` 里跑通了三种**官方内容没有等价物**的机制：

| 机制 | 靠什么写出来 | 证明了什么 |
|---|---|---|
| **血契**：消耗自己 15% 当前生命，换 3 倍爆发 | `ctx.entity(self.id)` 读真实 hp + 对自己 `ctx.damage` | 能读状态、能打自己 |
| **回响**：记住目标上次的血量，它回过血就按 2 倍惩罚 | 包内**模块级 `Map`** 跨次施放存活 | 能持有战斗内记忆 |
| **蓄能→引爆**：叠 5 层后清空并按层数结算 | `ctx.applyBuff` + `ctx.buffStacks` + `ctx.removeBuff` | 技能之间能协作 |
| **新敌人**：注册怪物 + 遭遇，用包自己的技能组队 | `monster()` / `encounter()` | 40 个种子里确实被抽到并打完了 |

写不出来的（当前边界）：
- **召唤新实体、改速度轴、插入额外 GCD** —— 宿主根本没暴露这类操作，不是"不给权限"，
  是引擎没有这个能力。要做得先改 core（官方也做不了）
- Buff 只能是**乘数修正**（attackMul / damageTakenMul…），不能带自己的触发逻辑

## ⚠️ 带状态的包：现在有了正确的写法

实测过的事实：包内模块级 `Map` **活过整场战斗**，于是

> 同一池、同一种子、同一序列，**只因为先打过一场**，第二场的结果就不一样。

测试里两边都钉住了（`sandbox-mechanics.test.js`）：不挂钩子 ⇒ 两场不同；挂了
`onBattleStart` ⇒ 逐字节相同。

**正确写法**：把跨次施放的记忆放进模块级变量，并在每场开头自己清掉：

```js
const seen = new Map();
onBattleStart(() => { seen.clear(); });   // ← 一行把"单场可复现"拿回来
```

不挂也行（游戏不会坏），但要知道后果：**装了这类包之后，分享种子只能复现整局，
不能单独复现某一层**。官方内容全无状态，所以以前没这个问题。


## 一分钟上手

```bash
mkdir -p src/mods/dev/mymod
# 可信层：写 manifest.js（声明）+ setup.js（产出内容）
# 第三方写法：写 manifest.json + index.js，import 'fate'
npm run dev
```

控制台会打出你 `context.log()` 的内容，以及 `[mods] 已加载 N 个模组：技能 … / 怪物 …`。
加载失败会**整局起不来**并明确报出是哪个模组的哪个字段 —— 这是有意的（见下文"护栏"）。

### 最小可运行的模组

```js
// src/mods/dev/mymod/manifest.js
export default {
  id: 'mymod.basic',        // 全局唯一，重复会报"模组 id 重复"
  version: '1.0.0',
  type: 'content',          // 'content'（默认）或 'system'（可注册契约实现）
  provides: [],
  requires: [],
};
```

```js
// src/mods/dev/mymod/setup.js
export function setup(context) {
  // 契约符号从 context 拿，用闭包捕获进 execute —— 不需要 import 任何 core 内部
  const { damageApply, audioPlay } = context.contracts;
  context.log('我的第一个模组');

  return {
    skills: [
      {
        id: 'mymod.slash',
        name: '我的斩击',
        description: '造成 1.2 倍攻击力的伤害。',
        type: 'GCD',
        gcdCost: 2.4, // 单位是「秒」；2400ms 是 16 的整数倍 ✓
        range: 'single',
        power: 1.2,
        tags: ['physical'], // 想进流派筛选就得打官方流派标签（或自己注册流派，见下）
        condition: null,
        soundId: 'combat.hit',
        buffId: null,
        execute(ctx, self, targets) {
          const damage = ctx.get(damageApply);
          const audio = ctx.get(audioPlay);
          for (const target of targets) {
            const result = damage({
              sourceId: self.id,
              targetId: target.id,
              amount: self.attack * 1.2,
            });
            audio({ soundId: result.isCrit ? 'combat.crit' : 'combat.hit' });
          }
        },
      },
    ],
  };
}
```

这段是可以直接跑的。示例包里的 `void.rift` 就是它的加长版。

## 加载机制（六步，任一步失败就整体失败）

```
1 发现     glob 扫 src/mods/**/manifest.js（含 official/ 与 dev/）
2 读声明   每个目录还要有 setup.js 或 index.js，导出 setup 函数
3 依赖图   provides / requires 建边，检测环
4 拓扑排序 被依赖的先加载；src/mods/dev/ 强制排最后
5 实例化   按序调用 setup(context)，把返回值合并进内容池
6 校验     全部加载完后统一查跨引用（悬空 ID 直接抛错）
```

**为什么"任一模组出错就整体失败"**：部分加载会留下悬空引用（怪物引用了没注册的技能、
技能引用了没注册的 Buff），那种状态在战斗里表现为"看上去生效其实零效果"，
排查成本远高于启动时直接报错。

**后加载覆盖先加载**：`dev/` 在最后，所以它可以就地改官方内容（同 id 即覆盖）。

## `setup(context)` 的输入

| 字段 | 是什么 |
|---|---|
| `context.registry` | 契约注册表。`system` 模组可以往里 register 实现 |
| `context.contracts` | 核心契约符号映射：`damageApply / healApply / buffApply / stateQuery / prngNext / combatLog / audioPlay` |
| `context.modId` | 你的模组 id。会作为 `source` 字段写进每一条内容 |
| `context.log(msg)` | 带 `[mod:你的id]` 前缀的日志 |

## 返回值：八种产物，给什么注册什么

```js
return {
  families:       [ … ],  // 流派注册（见下节）
  skills:         [ … ],
  buffs:          [ … ],
  monsters:       [ … ],
  encounters:     [ … ],
  shopItems:      [ … ],
  events:         [ … ],
  mapGenerators:  [ … ],
};
```

## 六条硬约束（都会被加载期或 lint 拦住）

| # | 约束 | 违反时的报错 |
|---|---|---|
| 1 | `execute` / `condition` **必须同步** | `技能 x 的 execute 不能是 async（规格 5.3）` |
| 2 | 一切时间量必须是 **16ms 的整数倍**（写秒，normalize 换算） | `… 的时间量必须对齐到 16ms 的整数倍` |
| 3 | 副作用**只能走契约**，不许 import core 内部去改状态 | lint：`core/**` 禁 async / `Math.random` / `Date.now` |
| 4 | 随机只能用 `context.rng()`（战斗流）。**什么时候摇骰子属于确定性的一部分** | 无报错，但会破坏跨速度对拍 |
| 5 | 不许碰 DOM、不许直接读存档 | 架构约束（`mods/` 不 import `ui/`；示例包除外见下） |
| 6 | 永久属性必须走 `addPermanentBonus(player, {...})` | 有守卫测试扫官方与示例内容里的 `state.player.maxHp =` 写法 |

第 2 条的原因：冷却与 Buff 存的是**绝对到期时刻**（`readyAt` / `expiresAtMs`），
只比较大小、不逐帧递减。时长不对齐 16ms，4x 的 64ms 步长就会跳过判定边界，
同一种子在 1x 和 4x 下打出不同结果。

## 能力从哪里来：`ctx` 与 `ops`

技能的行为**不需要认识 Symbol** —— 引擎把能力直接挂在 `ctx` 上：

```js
execute(ctx, self, targets) {
  for (const t of targets) {
    const r = ctx.damage({ sourceId: self.id, targetId: t.id, amount: self.attack * 1.2 });
    ctx.sound(r.isCrit ? 'combat.crit' : 'combat.hit');
    ctx.applyBuff({ targetId: t.id, buffId: 'abyss.mark', stacks: 2, durationMs: 8000 });
    ctx.log(`${self.name} 刻下印记`);
  }
}
```

| ctx 上有什么 | 说明 |
|---|---|
| `damage / heal / applyBuff / removeBuff` | 四个效果，返回 `{dealt, isCrit, targetHp, lethal}` 等纯数据 |
| `buffStacks(entity, buffId)` `hasBuff(entity, buffId)` | 读某个实体身上的 Buff 层数（不在场返回 0） |
| `entity(id)` | 按 id 取实体快照 |
| `query(path?)` | 读全局状态，如 `'player.hp'`、`'monsters'` |
| `rng()` | 战斗流随机数。**每调一次就推进一次序列** |
| `log(msg)` `sound(id)` | 写战斗日志 / 放音（无音频资源时静默） |
| `virtualTime` `floorNumber` | 只读 |

商店与事件用第二个参数拿能力：

```js
apply(state, ops) {
  ops.permanentBonus({ attack: 5, maxHp: 25 });
  if (ops.spendShards(30)) ops.permanentBonus({ attack: 10 });   // 不够就什么都不做
  ops.gainShards(25); ops.hpCostRatio(0.15); ops.healRatio(0.4); ops.fullHeal();
}
```

`ops` 一共 9 个：`permanentBonus shards gainShards spendShards setShards healRatio
hpCostRatio fullHeal addMetadata`。**不要直接写 `state.player.maxHp += 60`**（见下文
"永久成长"）。

### ⚠️ 一条会静默失效的坑：不要用 `query` 路径取实体

```js
ctx.query(`monsters.${target.id}.hp`)   // ← 永远返回 undefined
```

原因：状态路径按 `.` 分段，而**实体 id 本身就含点**（`mon.thunder.herald.t1#0`、
`blade.jab`）。所以路径会被切碎，取到 `undefined`，然后你的技能安静地走"读不到"的
分支 —— 看上去生效其实没生效，是最难查的一类 bug（示例包里的 `void.ruin` 一开始就是这么坏的）。

正确写法：`ctx.entity(id)`、`ctx.buffStacks(entity, buffId)`、`ctx.hasBuff(...)`。
`query` 留给非 id 路径（`'player.hp'`、`'monsters'`、`'monsters.0.hp'` 这种数字下标）。

## 七个契约的签名

`ctx.get(symbol)` 拿到实现函数；也可以用 `ctx.call(symbol, args)` 一步到位。

| 契约 | 调用 | 返回 | 注意 |
|---|---|---|---|
| `damageApply` | `({sourceId, targetId, amount, canCrit?, critChance?})` | `{dealt, isCrit, targetHp, lethal}` | 目标已死时返回 `dealt: 0` 且**不消费随机数** |
| `healApply` | `({sourceId, targetId, amount})` | `{healed, targetHp}` | 溢出部分丢弃，不会把 hp 抬过 maxHp |
| `buffApply` | `({targetId, buffId, stacks, durationMs, maxStacks?})` | 施加结果 | `durationMs` 必须是 16 的整数倍，否则**运行期**抛 ContractViolation |
| `stateQuery` | `(selector?)` selector 可为 `'player.hp'` 这样的路径或函数 | 深冻结只读副本 | 写它会在严格模式抛错；别指望改状态 |
| `prngNext` | `()` | `[0,1)` | 推进**战斗流**。调用次数改变 = 结果改变 |
| `combatLog` | `(message)` | — | 进 `state.log`，容量固定 100 条 |
| `audioPlay` | `({soundId, volume?})` | `undefined` | 永不影响逻辑；没有音频资源时静默丢弃 |

`ctx` 上还有两个只读属性：`ctx.virtualTime`（毫秒）、`ctx.floorNumber`，
以及 `ctx.rng()`（等价于 `prngNext`）。

### 技能可用的 range

`self` / `single` / `allEnemies` / `allAllies` / `randomEnemy`。
其中 **`randomEnemy` 会消费一次随机数** —— 这是"什么时候摇骰子"的一部分，
把它换成 `single` 会让同一种子的整场战斗分叉。

## 内容字段速查

### skill

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 全局唯一 |
| `type` | ✓ | `'GCD'` 或 `'oGCD'` |
| `execute` | ✓ | 同步函数 `(ctx, self, targets)` |
| `gcdCost` | GCD 用 | 秒。默认 2.5 |
| `cooldown` | oGCD 用 | 秒。默认 30 |
| `range` | | 默认 `single` |
| `name` `description` | | 缺省用 id / 空串 |
| `power` | | 展示用倍率（战斗屏、图鉴会显示 ×N） |
| `priority` | | oGCD 平局用；玩家槽位优先级更高 |
| `tags` | | 数组。流派标签决定它进哪个筛选组与解锁轮转组 |
| `condition` | | `(ctx, self, targets) => boolean` 或 null |
| `buffId` | | **引用未注册的 Buff 会在加载期被拦**（否则会静默零效果） |
| `buffDuration` | 配 buffId | 秒 |
| `soundId` | | 不在清单里的 id 会被静默忽略 |

### buff
`id` ✓、至少一个乘数字段 ✓（`attackMul / defenseMul / damageDealtMul / damageTakenMul / healMul`），
`isDebuff`、`name`、`description` 可选。**一个修正都没有的 Buff 会被拒绝加载。**

### monster
`id` ✓、`maxHp` / `attack` / `defense` 必须是非负整数 ✓、`gcdSequence` 非空 ✓，
`ogcdSlots`（≤3）、`tier`（`normal` / `elite`）、`tags` 可选。

### encounter
`id` ✓、`monsterIds` 非空且 **≤6** ✓，`tier`、`minFloor`、`maxFloor`（默认无限）、
`weight`（默认 10）可选。
**注意 `maxFloor`**：官方模板最深到 999 层；不写就默认无限，写了 999 而玩家在第 1000 层
会由 `pickEncounter` 回退到最深一档（不崩，但难度不再爬升）。

### shopItem
`id` ✓、`cost` 非负整数 ✓、`apply(state)` ✓，`name` / `description` / `kind` / `weight` 可选。
`apply` 收到的是**探索状态的 draft**，可以直接改 `fateShards`、`player.hp`，
但永久属性必须走 `addPermanentBonus`（见下）。

### event
`id` ✓、`choices` 非空 ✓，每项 `{label, description, apply(state)}`。
`weight`、`text`、`name` 可选。设计约定：每个选项都该是"取舍"而非纯赠礼。

### mapGenerator
`{ id, name, generate({ seed, floorNumber }) }`，返回
`{ nodes, adjacency, startNodeId, exitNodeId, gridWidth, gridHeight }`。
`GameFlow.enterFloor` 目前取的是 **`official.grid` 这个 id** —— 想换地图算法，
就用同名 id 覆盖（官方包自己也是这么注册的）。

## 流派：注册制，不是硬编码

`buildUnlockTable` 把 GCD 按**流派轮转**排（每族最便宜的先上，再每族第二便宜……），
所以"加一个新流派"必须让系统知道它存在：

```js
return {
  families: [{ id: 'void', label: '虚空' }],
  skills: [{ id: 'void.rift', tags: ['void'], … }],
};
```

- 不注册流派，你的技能会被归进 `untagged`，在轮转里排到最后 → 玩家很晚才见到它们
- 1 级解锁名额会自动等于流派数（官方 6 个 ⇒ 6 个名额；你加第 7 个 ⇒ 7 个），
  保证**每个流派在 1 级都有一个可用技能**
- 图鉴与序列屏的流派筛选按钮从 `pool.families` 生成，注册即出现在 UI 里

## 永久成长：只有一条路

```js
// 可信层（官方模组）
apply(state) {
  addPermanentBonus(state.player, { attack: 5, maxHp: 25 });   // 支持负值
}

// 第三方包：拿不到 core，走 ops
apply(state, ops) {
  ops.permanentBonus({ attack: 5, maxHp: 25 });
}
```

**为什么不能直接写 `state.player.maxHp += 25`**：`maxHp / attack / defense / critChance`
是派生值，由 `(exp, equipment, seedBonus, permanentBonus)` 每次重算 —— 直接赋值会在
下一次 `recalcPlayer` 时凭空消失（官方商店历史上就是这么坏的，现在有守卫测试扫这种写法）。

`state.player.hp` 不是派生值，可以直接改。但重算遵循"**保持缺失量**"，
所以加上限等于回等量生命，减上限等于掉等量生命。

## 覆盖官方内容

同 id 即覆盖，`dev/` 最后加载所以总是赢。三条规则：

1. **整条替换，不是字段合并** —— 只写 `{id, name}` 会把原定义的 `execute` 弄丢，
   然后被 normalize 拒绝。要覆盖就写全。
2. **覆盖会改变确定性表现** —— 同一种子在不同模组组合下结果不同，这是设计允许的。
   但别在同一个存档槽上混用两套模组来回读档。
3. **想"只改一个字段"**：目前没有提供合并语义的 API。最实用的做法是照抄官方定义
   再改（官方内容都在 `src/mods/official/` 下，是纯 ESM，可以直接读）。

## 调试与自测

```bash
npm run dev                  # 启动失败会把 ModLoadError 的 message 与 code 摊在错误屏上
npm test                     # 含"官方 + 示例模组一起加载"、fate API 契约、dev/ import 边界

node tools/mod-shape-report.mjs   # 内容形状报告：工厂覆盖率、谓词种类、状态操作种类
```

三条与模组有关的守卫测试，改 API 时会拦住你：
- `tests/integration/mod-example.test.js`：官方 + 示例包一起加载、模组流派参与轮转、
  五条加载期护栏（悬空引用 / async execute / 非 16ms 对齐 / 零效果 Buff / id 重复）
- `tests/unit/fate-api.test.js`：`fateApiKeys()` 与 shim 导出一致；ctx/ops 真的提供
  声明的能力；**dev/ 目录只准 import 'fate' 与相对路径**
- `tools/mod-shape-report.mjs` 的输出是"包格式该支持哪些操作"的依据，改内容后重跑

示例包本身就是回归对象：`tests/integration/mod-example.test.js` 会加载它并断言
流派进轮转、normalize 生效、契约能打出伤害、护栏会拦住坏模组。**照抄它最省事。**

### 常见报错对照

| 报错 | 意思 | 怎么修 |
|---|---|---|
| `模组 id 重复：x` | 两个 manifest 用了同一个 id | 换 id |
| `fate.skill(...) 之前必须先调用 fate.begin(...)` | 注册顺序错了：`begin` 要在所有 `skill/monster/...` 之前 | 先 `begin()` |
| `ctx.query('monsters.xxx.yyy')` 返回 undefined | id 含点，路径语法表达不了（见上文坑） | 改用 `ctx.entity(id)` / `ctx.buffStacks()` |
| 包能跑但 zip 装不上 | 示例包 import 了 core | 只 import 'fate' 与相对路径（有 lint 测试拦） |
| `无法加载 manifest：…` | 文件语法错（例如注释里写了 `**/`，把块注释提前闭合） | 看行列号 |
| `内容池存在 N 处悬空引用` | 怪物/遭遇/Buff 引用了不存在的 id | 检查拼写与加载依赖 |
| `技能 x 的 execute 不能是 async` | 约束 1 | 拆成同步 |
| `… 必须对齐到 16ms 的整数倍` | 约束 2 | 换个数：2.4 / 3.2 / 12 都安全 |
| `Buff x 未声明任何修正` | 零效果 Buff | 删掉或加乘数 |
| `没有适用于第 N 层的 normal 遭遇模板` | 你的遭遇 `maxFloor` 太小 | 放宽区间（示例包用 999） |

### 已知的架构小瑕疵

- 官方 `core-skills/helpers.js` 里 `import` 了 `ui/audio/soundMap.js` 拿音效 id。
  严格说 `mods/` 不该依赖 `ui/`。你自己写模组时**把 soundId 当字符串字面量**就行，
