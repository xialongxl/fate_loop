# 模组沙箱与包格式设计

> 状态：**S0 POC 与 S2 沙箱实现均已完成**（2026-08-30）。代码在 `src/core/mods/sandbox/`，
> 验收测试 `tests/unit/sandbox-host.test.js` + `tests/integration/sandbox-pack.test.js`
> + `tests/integration/app-packs.test.js`。当前**只开放 `family/skill/buff/monster/encounter`
> 五类注册**，`shopItem/event/mapGenerator` 是**显式报错**而不是静默丢。下一步 S3（管理界面）。
> S0 实测数字（2026-08-29，本机 Node 24 + quickjs-emscripten 0.32）：
>
> | 探针 | 结果 |
> |---|---|
> | wasm 体积 | release-sync **491KB raw / 227KB gz**；release-asyncify 1003KB / 356KB |
> | 死循环 | ✓ 被 `setInterruptHandler` 掐住（墙钟 200ms 时中断回调仅 689 次） |
> | 内存 2MB 上限 | ✓ 拦截 |
> | 栈 256KB + 无限递归 | ✓ 拦截（**注意**：栈上限设太大时递归会直接把宿主进程打崩，必须设小） |
> | 一次跨界 `execute`（3 目标 + 3 次宿主调用） | **56 µs** ⇒ 300 次施放的一场战斗 ≈ **17 ms** |
> | 多文件包 `setModuleLoader` | ✓ 模块图解析成功 |
>
> 两个 S2 必须记住的坑：① 中断预算要按**墙钟**算，按回调次数算实测会一卡 6 秒；
> ② 包是 ESM，`import()` 返回 promise，注册收集必须在 microtask 跑完之后再做。
> 决策：保留 JS 作为模组语言，第三方包在 **QuickJS-WASM** 里执行
> 起因：要支持"玩家一键加载别人的 mod"（GitHub Pages 无后端），而构建期打包的
> 原生 ESM 模组等于把陌生人的代码放进同源全权环境 —— 这两件事不能同时成立。

## 1. 决策记录

### 1.1 为什么必须动

| 事实 | 出处 |
|---|---|
| 模组是构建期打包的（`import.meta.glob` 在 build 时展开成静态 import 图） | 实测：`dist/assets/setup-*.js` 里能 grep 到技能名 |
| 因此"装 mod"目前只有 fork + 重新 build 一条路 | 同上 |
| 产品要求：玩家是来玩的，不是来当极客自己构建的 | 本次讨论的决定性输入 |
| 计划书要求模组能注入**新技能、新怪物、新地图生成逻辑** | 完整设计计划书 第 27 行 |
| 计划书要求"模组作者只能调用契约，不能直接触碰私有状态" | 完整设计计划书 第 253 行 |

关键洞察：**"新机制"只需要一个新的 `execute` 闭包，不需要改 core。** 官方技能由
工厂模板生成的对象，和模组手写的 `execute` 产出的对象是同一种东西。所以只要沙箱
能跑 JS，计划书的全部承诺都能保留 —— 这是放弃"JSON 数据包"方案的根本原因。

### 1.2 被否掉的方案

| 方案 | 否掉的理由 |
|---|---|
| **只支持 fork + 自己 build** | 与"玩家装包"的产品目标冲突 |
| **JSON 数据包 + 固定效果词汇表** | 违反计划书第 27 行：模组不能造新机制。测量显示官方内容 100% 是"4 个工厂 + 6 种谓词 + 11 种操作"，所以 JSON 能覆盖**今天的全部内容** —— 但也就到此为止，词汇表外的一切要等引擎版本 |
| ~~zip / modpack 容器~~ | ~~不需要素材~~ **这条判断错了，已推翻**：zip 的价值是**多文件打包**，与素材无关。官方模组自己就是 2~5 个文件（实测 `core-skills` 5 个、`core-encounters` 5 个），要求第三方压成单文件等于让作者手工做 bundling。见 §5.1 修订 |
| **单个自包含 `.js`（原 §5.1 提案）** | **已推翻**：与"模组是多文件的"这个事实冲突。单文件仍然合法，但它只是"只有一个文件的包"，不是格式要求 |
| **不透明源 iframe + Worker 跑整个战斗模拟** | 隔离最强（连卡死都能 terminate），但要把 `BattleEngine` 搬进沙箱 realm，边界重构量最大。列为 C 方案撑不住时的升级路线 |
| **SES / Compartment（同 realm 冻结）** | 改动最小且保住同步调用，但**无法计量** —— 一个 `while(true)` 就冻住整个页面，而"点了别人的包然后必须刷新页面"是玩家不能承受的失败模式 |
| **只做知情同意，不隔离** | 那不是安全，是免责标签。恶意包仍可清存档、注入钓鱼 UI、发请求 |

### 1.3 为什么是 QuickJS-WASM

1. **真计量**：`shouldInterrupt` 回调可以按"已执行指令数 / 已耗时"从宿主侧中断脚本
   → 无限循环从"页面卡死"降级为"这个包被停用"。这是选它而不是 SES 的决定性理由。
2. **内存上限**：`setMemoryLimit` 直接挡掉吃光内存的包。
3. **默认无能力**：VM 里没有 `fetch` / `localStorage` / `document` / `Date` /
   `Math.random`，除非宿主注入。宿主只注入契约函数 → 计划书第 253 行从"纪律"
   变成"物理事实"。
4. **确定性更好**：没有宿主时钟与随机源，mod 的随机只能走 `prng.next` 契约
   → 摇几次骰子变成可审计的。
5. **模组作者体验几乎不变**：写的还是 JS。限制是"不能用 async、不能 import、
   跨边界只能传可序列化值" —— 而我们的契约本来就只传 `{sourceId, targetId, amount}`
   这类纯数据，契合度高。

### 1.4 代价（必须承认）

- **体积**（实测 + 已落地）：release-sync 的 wasm **491KB / gzip 227KB**。本作入口
  chunk 现在 gzip **57.6KB**（旧文档写"约 28KB"早已过时）。懒加载已落地并核对过产物：
  `host 4.8KB + emscripten-core 11KB + browser 胶水 4.2KB + wasm 227KB`（均 gzip）
  全在按需 chunk 里，**入口 chunk 不含 QuickJS 任何一块** ⇒ 没装包的玩家一个字节都
  不多下。一个必须直连变体的理由：引根包 `quickjs-emscripten` 会把 **4 个变体
  （~3MB wasm）** 全拖进构建。
- **性能**（实测）：一次 `execute`（3 目标 + 3 次宿主契约调用）约 **56 µs**，
  典型一场 300 次施放的战斗多花 **17 ms** —— 可接受。极端上限（10k 步 × 4 实体
  每步都放）约 2.3 s，但真实战斗受 GCD 限制到不了那个量。
- **不能自托管 CDN 之外的来源**：wasm 与 loader **必须 vendoring 进仓库**并固定
  版本 + SRI，不能从第三方 CDN 拉 —— 否则"引入沙箱"这件事本身变成新的供应链风险。

## 2. 目标与非目标

**目标**
- G1 玩家能在不 build 的前提下加载第三方包，且包**无法**读取/破坏主存档、无法访问 DOM、无法发网络请求
- G2 包能定义新技能（含新的 `execute` 行为）、Buff、怪物、遭遇、商品、事件、流派，**以及新的地图生成逻辑**
- G3 卡死/吃内存的包只导致该包被停用，不拖垮页面
- G4 装包前后，"同种子同结果"仍然成立，且**内容集合可辨识**（内容指纹）
- G5 官方内容与 fork 作者的原生 ESM 模组路径**完全不变**
- G6 第三方包与官方包**写法形状一致**：多文件、相对 import、`execute` 是真函数；
  唯一差别是能力从 `'fate'` 拿而不是从 `core/**` 拿（§5.1、§5.6）

**非目标**
- N1 不做在线工坊/订阅源（分发索引留到 S4 之后另案）
- N2 不支持包内素材（音频、图片）—— 没有需求
- N3 不追求"防同 realm 侧信道"级别的对抗性安全（见 §4.3）
- N4 不做包之间互相依赖的解析（第一版每个包自包含）

## 3. 两层模组架构

```
┌─ 第 1 层：原生 ESM 模组（可信） ─────────────────────────┐
│  src/mods/**  →  import.meta.glob  →  构建期打包         │
│  能力：无限制（能 import core，能注册契约实现）           │
│  谁：官方内容、fork 作者、开发者                          │
│  现状：就是今天的样子，不改                               │
└─────────────────────────────────────────────────────────┘

┌─ 第 2 层：运行时包（不可信） ────────────────────────────┐
│  玩家选文件 / 拖拽 / 粘贴文本  →  sha256 + 源码确认       │
│  →  QuickJS-WASM 里求值  →  调 fate.register* 注册内容    │
│  能力：只有宿主注入的契约 + 预算限制                      │
│  谁：下载别人写的包的玩家                                 │
└─────────────────────────────────────────────────────────┘
```

**对计划书 3.2 的修订**：原文"第三方模组与官方模组在加载机制上无任何区别"要改成
"两层机制：官方与开发者走原生 ESM；不可信包走沙箱，能力受限于契约"。
理由：那条"无区别"正是安全问题的来源，而它带来的好处（自举、同一套校验）通过
**两层共用同一个 merge/validate 管线**仍然保留。

## 4. 威胁模型

### 4.1 沙箱挡住的

| 攻击 | 怎么挡 |
|---|---|
| 清/偷存档（IndexedDB、localStorage） | VM 里没有这些全局；且 modded 运行另有独立库（§7） |
| 注入钓鱼 UI、劫持页面 | VM 里没有 `document` |
| 外发数据、打点、SSRF | VM 里没有 `fetch`/`XMLHttpRequest`/`WebSocket` |
| 读时钟破坏确定性 | 没有 `Date`/`performance`；时间只能从 `ctx.virtualTime` 拿 |
| 自己造随机破坏复现 | 没有 `Math.random`（宿主注入受限的 `Math`）；随机只能走 `prng.next` 契约 |
| 无限循环 / 递归爆栈 / 吃内存 | `shouldInterrupt`（指令数 + 墙钟双预算）、`setMemoryLimit`、`stackSizeLimit` |
| 直接改战斗状态 | 跨界只能拿可序列化快照；写状态只能通过契约 |
| 注册超大内容拖垮加载 | 包体与条目数硬上限（§5.4），schema 校验在求值**之前** |
| zip bomb（512KB 压缩包解出 4GB） | 解压后总大小上限 2MB + 逐条目累计检查（§5.4） |
| 包内 import 穿越到宿主（`'../../core/derived.js'`） | §5.5 解析器：规范化后必须在包根内，否则拒绝 |
| 包从网络拉第二级载荷 | 没有 `fetch`，且解析器拒绝 `http(s)://` 与裸模块名 |

### 4.2 沙箱挡不住的（要靠别的手段）

| 残余风险 | 缓解 |
|---|---|
| 包让游戏变得不合理（1 血小怪给 1e9 经验） | 数值范围校验 + 存档标记"由 mod 产生" + 玩家可一键停用 |
| 文案注入（技能名塞 HTML） | UI 已全量 `escapeHtml`、日志用 `textContent`；**必须加测试守住**（这是包带来的第一个陌生文本源） |
| 恶意但"合法"的内容（把玩家存档进度变没意义） | 内容指纹 + 独立命名空间，玩家随时能看出"这不是原版那一局" |
| 沙箱本身的漏洞（QuickJS/wasm 的 CVE） | 版本固定 + SRI + vendoring，不追新；把 QuickJS 当依赖看待 |
| 供应链：包作者诱导你"再装一个包" | 每个包都要单独确认；不做"信任作者后自动放行" |

### 4.3 明确不承诺的

不做对抗性安全。我们防的是"一个普通恶意/劣质包在玩家不知情时搞坏游戏"，
不防"针对 QuickJS 版本的内存漏洞利用"。文档与 UI 都不该写成"绝对安全"。

**注意包格式变更带来的新面积**：多文件 + zip 意味着多了"解压器"和"路径解析器"两个
攻击面（zip bomb、路径穿越、符号链接条目）。对策在 §4.1 与 §5.5；符号链接在浏览器侧
不存在（zip 条目按普通文件处理），但**解压器要显式忽略非普通文件条目**，别指望默认安全。

## 5. 包格式规范（草案 v1）

### 5.0 先定抽象：包 = 一组「路径 → 文本」

引擎内部只认这一个数据结构：

```js
pack = { files: Map<路径, 文本>, entry: 'abyss.js', manifest: {...}, sha256: '…' }
```

四种入口都产出一个 `pack`，之后的流程（哈希 → 确认 → 沙箱求值 → 走现有
normalize + 跨引用校验）**完全不分叉**：

| 入口 | 实现 | 说明 |
|---|---|---|
| 拖一个 **zip** | `fflate.unzipSync`（~8KB gzip） | 发布/分享的标准单位 |
| 拖一个**文件夹** | `DataTransferItem.webkitGetAsEntry()` 递归读 | 作者本地最方便，零依赖 |
| 选文件（`<input type=file multiple>` / `webkitdirectory`） | 同上 | 兜底：拖拽在部分环境不可靠 |
| 粘贴**单个 `.js`** | 直接构造 files | 一行改动型包；本质是"只有一个文件的包" |

> **待实测**：`webkitGetAsEntry` 在各浏览器的现状（Firefox 支持但拖文件夹行为有差异）；
> 现代替代是 File System Access API 的 `FileSystemDirectoryHandle`，但 Chrome/Edge only。
> 所以 zip 是主路径，文件夹拖拽是便利路径。

### 5.1 一个包 = 一个目录（多文件，写法与官方模组几乎一致）

```
abyss.mod/
├── manifest.json        { id, version, title, author, description, entry: "index.js" }
├── index.js             入口：import 'fate' 与包内相对路径
├── skills.js            技能定义（含 execute 闭包）
├── monsters.js
└── encounters.js
```

```js
// index.js —— 包入口
import { begin, family, buff, monster, encounter, finish } from 'fate';
import { ABYSS_SKILLS } from './skills.js';        // 包内相对路径：允许

begin({ id: 'someone.abyss', version: '1.0.0', title: '深渊补充包', author: 'someone' });
family({ id: 'abyss', label: '深渊' });
buff({ id: 'abyss.mark', name: '深渊印记', isDebuff: true, damageTakenMul: 1.15 });
monster({ id: 'mon.abyss.wisp', name: '深渊游魂', maxHp: 88, attack: 24, defense: 6,
  gcdSequence: ['abyss.reap', 'blade.jab'], tags: ['abyss'] });   // 引用官方技能用 ID 字符串
finish();
```

```js
// skills.js —— 新机制就在这里：execute 是真函数
import { contract, SKILL_TYPE, SKILL_RANGE } from 'fate';

export const ABYSS_SKILLS = [
  {
    id: 'abyss.reap', name: '收割', type: SKILL_TYPE.GCD, gcdCost: 2.4,
    range: SKILL_RANGE.SINGLE, tags: ['abyss', 'execute'],
    description: '引爆目标身上全部深渊印记，每层追加 25% 倍率。',
    execute(ctx, self, targets) {
      const damage = ctx.get(contract.damageApply);
      const query = ctx.get(contract.stateQuery);
      const remove = ctx.get(contract.buffRemove);
      for (const t of targets) {
        const stacks = query(`monsters.${t.id}.buffs.abyss.mark.stacks`) ?? 0;
        damage({ sourceId: self.id, targetId: t.id, amount: self.attack * (1 + 0.25 * stacks) });
        if (stacks > 0) remove({ targetId: t.id, buffId: 'abyss.mark' });
      }
    },
  },
];
```

**与官方模组的唯一差别**：官方写 `import { SKILL_RANGE } from '../../../core/constants.js'`，
第三方写 `import { SKILL_RANGE } from 'fate'`。其余（多文件、相对 import、`execute`
是真函数、用 ID 字符串跨包引用）完全一致 —— 这才对得上计划书 3.2 的自举精神。

### 5.2 宿主注入给包的能力清单（白名单，其余一律没有）

| 注入 | 说明 |
|---|---|
| `fate.begin/family/buff/skill/monster/encounter/shopItem/event/generator/finish` | 注册 API |
| `ctx.contract(name)` | 七个契约的包装：`damageApply healApply buffApply stateQuery prngNext combatLog audioPlay`（v1 再加 `buffRemove`） |
| `ctx.virtualTime` `ctx.floorNumber` | 只读，来自引擎 |
| `fate.permanentBonus / gainShards / spendShards / healRatio / hpCostRatio / fullHeal / addMetadata` | 探索态安全原语（对应测出的 11 种操作） |
| `Math`（去掉 `random`）、`JSON`、`Object/Array/String/Number/Boolean`、`Map/Set` | 语言基座 |

**故意不给**：`Date`、`performance`、`fetch`、`Worker`、`document`、`localStorage`、
`indexedDB`、`console`（用 `ctx.log` 代替，走 combatLog 并计入预算）、`eval`/`Function`。

### 5.3 加载流程

```
选文件/拖拽/粘贴
  → 计算 sha256
  → 确认面板：包名、作者、版本、哈希（与来源处公布的比对）、源码全文可展开
  → 求值（QuickJS，预算内；只允许注册，不允许其他副作用）
  → fate.finish() 收集产物
  → 走与官方内容**同一条** normalize + validatePoolReferences 管线
  → 失败：整包拒绝，明确报出是哪条内容哪个字段（复用现有 ModLoadError 文案）
  → 成功：写入已装列表（含哈希），重算 contentHash，提示"本局内容与原版不同"
```

复用现有管线是关键决定：**不为包另写一套校验**。官方内容今天怎么被 normalize
和查悬空引用，包就怎么被处理 —— 这样包作者能拿到和官方一样的报错信息。

### 5.4 硬上限（求值前 + 注册时双重检查）

| 项 | 上限（初值，可调） |
|---|---|
| 包内文件数 | 32 |
| 单个源文件 | 128 KB |
| 包总大小（zip 压缩后） | 512 KB |
| **zip 解压后总大小** | 2 MB（**zip bomb 防护**，原设计漏项） |
| 粘贴的单文件包 | 256 KB |
| 技能 / 怪物 / 遭遇 / Buff / 商品 / 事件 各 | 200 / 500 / 300 / 100 / 50 / 50 |
| 单个字符串（名称/描述/文本） | 200 字符 |
| 数值字段（倍率、cost、maxHp、attack…） | 有限数且 `0 ≤ v ≤ 1e6`；倍率 ≤ 50 |
| 单场战斗里该包的契约调用次数 | 20 000（超出即判定失控并停用该包） |
| 单次 `execute` 的 VM 指令预算 | 50 000 步（`shouldInterrupt`） |
| VM 内存 | 32 MB |

### 5.5 模块解析规则（多文件包的核心）

沙箱里 `import` 不是浏览器那套，而是宿主实现的解析器。**只有三类能过**：

| import 目标 | 允许 | 解析到 |
|---|---|---|
| `'fate'`、`'fate/…'` | ✅ | 宿主注入的能力模块（§5.2 白名单） |
| `'./x.js'`、`'../y/z.js'` 且**规范化后仍在包根内** | ✅ | 包自己的 files 表 |
| 绝对路径、`http(s)://`、`node:*`、裸模块名（`'lodash'`） | ❌ | 加载期拒绝，报"第三方包只能 import 'fate' 与包内相对路径" |
| `'../../etc/...'` 之类穿越出包根 | ❌ | 同上（路径必须先 normalize 再判前缀） |

实现上是 QuickJS 的 module loader 回调（`vm.setModuleLoader` / 自定义 resolver）：
拿到 specifier → 规范化 → 查 files → 没有就抛给宿主报错。**没有文件系统、没有网络**，
所以"能 import 什么"完全等于"包里有什么文件"，这是可穷举审计的。

一条附带规则：**入口文件名固定**（`manifest.json` 的 `entry`，默认 `index.js`），
其余文件只能被 import 到，不能自动执行 —— 否则"哪个文件先跑"会变成隐式顺序依赖。

### 5.6 `'fate'` 有两种解析方式：一份包源码，两个环境都能跑

这是本方案最值钱的一条结构决定：

```
构建期（可信层）   vite resolve.alias:  'fate' → src/mods/fate-shim.js
沙箱内（不可信层） 宿主 setModuleLoader: 'fate' → 注入的真实能力模块
```

于是同一个包目录：
- **作者**放进 `src/mods/dev/` → `npm run dev` 直接跑，改一行看一行，不用打包、不用 zip
- **玩家**拿到压好的 zip → 走沙箱路径加载
- 两边行为必须一致，因为 shim 只是"按第三方能看到的形状再导出 core 的能力"

三个附带好处：

1. **`fate-shim.js` 成为 API 契约的唯一声明处**。加一个能力必须同时改 shim 与沙箱注入，
   而一条"两边导出键集合相等"的测试就能守住漂移（不靠文档自觉）。
2. **可以加 ESLint 规则强制边界**：`src/mods/dev/**` 只允许 import `fate` 与相对路径
   （`no-restricted-imports`）。这样"第三方写法"由 lint 保证，跟本项目把纪律变成
   lint/测试 的惯例一致。
3. **示例包同时是文档、S2 测试夹具、zip 打包样本**，不用维护第二份重复内容。

代价与限制要说清：
- dev 示例包**不再享受官方 helpers 的工厂便利**（`damageSkill` 那套）。这是故意的：
  第三方不该偷偷依赖官方代码。若确实想要工厂级 API，正确做法是把工厂**搬进 `fate`
  模块**作为宿主提供的高层 API（S2 的设计选择）。
- 需要一条 vite 配置（alias）。dev 与 build 两条路径都要验证 alias 生效（列入 §10）。
- 可信层官方包（`src/mods/official/`）**继续直接 import core**，不受这条规则约束 ——
  它就是"可信层能做什么"的活示范，不需要再造一份。

## 6. 引擎侧改造点

1. **新增 `src/mods/sandbox/`**
   - `quickjsRuntime.js`：懒加载 wasm、创建 VM、注入白名单、预算与中断回调
   - `packHostApi.js`：`fate.*` 注册表 + 安全原语
   - `packLoader.js`：文本 → sha256 → 求值 → 产物 → 交给现有 `mergeIntoPool`
   - `packSchema.js`：硬上限与字段校验（复用 `invariant.js` 的断言）
   - `moduleResolver.js`：§5.5 的三类解析 + 路径规范化与穿越防护
   - `containers.js`：zip（fflate）/ 文件夹 / 单文件 → 统一的 `pack.files`
3. **`src/mods/fate-shim.js`**：可信层的 `'fate'`，按第三方可见的形状再导出 core 能力。
   与沙箱注入模块的导出集合必须相等（有测试守）。vite 配 `resolve.alias`。
4. **`execute` 调用点要能接受"来自 VM 的函数"**：对调用方透明（还是
   `skill.execute(ctx, self, targets)`），但 ctx 必须是**包装过的**：
   传入的 self/targets 是纯数据快照，返回后由引擎自己应用契约效果。
   ⚠️ 这是唯一可能碰热路径的地方，也是 S0 POC 必须量的东西。
5. **`stateQuery` 契约**：包拿到的必须是纯数据快照（今天它返回深冻结对象，
   跨 VM 需要 `structuredClone` 语义的转换 —— QuickJS 侧要 `dup`/`json` 转换）。
6. **错误与停用**：包内抛错 → 宿主 try/catch → 该包标记 `faulted`，本局停用并提示；
   连续超预算同理。**不允许**一个坏包把整局拖崩（对齐计划书"模组执行异常"条目）。
7. **内容指纹**（§7）与**已装包列表**要进 `state`（或独立的非确定性 UI 层？
   见 §7.2 —— 结论：进存档，不进战斗状态）。

## 7. 内容指纹与存档隔离

### 7.1 contentHash —— 让"抄种子复现"在装包后仍然成立

现在 `结果 = f(seed, 序列, 内容池)`。装包后内容池因人而异，所以复现凭据必须是
**种子 + 内容指纹**：

```
contentHash = fnv1a( 官方内容版本
                   + 每个已装包的 (id, version, sha256) 按 id 排序拼接 )
显示：头部种子旁 · 结算面板 · 历史战绩 · 存档摘要
文案：种子 20240101 · 内容 a1b2c3d4
```

- 哈希取**包源码字节**，不取求值结果（结果可能含函数引用，不稳定）
- 官方内容也要参与：今天 fork 改了官方数值，两个站的种子同样不复现 —— 所以这一项
  **与工坊无关，现在就有价值**（S1 先做的理由）
- 排序必须是 id 字典序，不能依赖加载顺序（与项目一贯的"平局打破靠字典序"同一条纪律）

### 7.2 存档独立命名空间

- 启用任何第三方包时，运行数据写入**另一个 IndexedDB 库**（如 `fate-loop-modded`），
  原版存档所在的 `fate-loop` 完全不被第三方代码路径触达
- 每条存档记录 `contentHash` + 包清单；读档时若清单缺失 → 明确提示
  "这个存档需要这些包：…（缺 X）"，而不是静默用不同内容恢复
- `contentHash` 存在 UI/持久层，**不进 `state` 的战斗字段**：它不是游戏状态，
  进了就会污染快照对拍与确定性断言

### 7.3 为什么顺序上先做这两件

它们和沙箱选型无关、体量小（各 ~100 行）、而且**即使最后不上沙箱也必须做**
（最坏情况的兜底）。先落地它们，后面无论走 C 还是退回 D 都不白干。

### 已实测（`npm run mod:poc`，2026-08-29）

- [x] 单次 host↔VM `execute`：约 56 µs；300 次施放 ≈ 17 ms
- [x] 中断：`setInterruptHandler` 能掐住死循环；**粒度粗**（200ms 墙钟只回调 689 次），
      所以预算必须按墙钟算 —— 按次数算实测会一卡 6 秒
- [x] `setMemoryLimit` / `setMaxStackSize` 都生效；**栈上限设太大（512KB）时
      无限递归会把宿主进程直接打崩**，256KB 才只抛 JS 异常
- [x] `setModuleLoader` 能解析多文件包与包内相对 import
- [x] 包是 ESM ⇒ `import()` 返回 promise，注册收集要等 microtask 跑完（POC 里没等到，
      注册回调为空 —— S2 必须处理）

### S2 实现期踩到的四处句柄/生命周期坑（quickjs-emscripten 0.32，代码里都有注释）

6. **`vm.undefined` / `vm.null` 是共享静态句柄**。`getProp` 读不到字段就返回它 ——
   对它 `dispose()` 等于把整个 context 的 `undefined` 杀掉，之后每一次属性读取都报
   `Lifetime not alive`，而且现场毫无提示。必须先判 `handle !== vm.undefined` 再 dispose。
7. **`JS_FreeRuntime` 发现 gc 对象表非空会直接 `abort()` 整个 wasm 实例** —— 不是 JS
   异常，try/catch 拦不住，页面一起没。所以"跑过包代码 / 被中断过 / 抛过错"的 runtime
   一律 **park 不 free**（代价有界：parked 数 ≤ 装包数）。它跟 S0 那条"栈上限设太大时
   无限递归会打崩宿主进程"是同一个坑的两面。
8. **`{type:'module'}` 求值返回的是 `undefined`，不是 `import()` 的 promise** ⇒ pump 会
   立刻判"已成功"，包里的**顶层 throw 静默消失**。要用脚本模式 `evalCode("import(...)")`。
9. **模块解析错误传不出来**：动态 `import` 的实例化在 job 队列里，宿主在
   `setModuleLoader` 里 throw 会被 `executePendingJobs` 吞掉。改成"记下第一个错、
   pump 结束后统一判定"，并用准确原因顶掉 QuickJS 那句没用的 `Could not find export…`。

另一处刻意的行为改动：**包在战斗里跑炸不再向引擎抛异常**，改成"标记失效 +
`onPackFailure` 上报一次 + 之后空转"。抛出去的惩罚落在正在打这局的玩家身上，
而不是写坏包的作者；因为上报通道存在，这也不算静默失败。

## 11. 一句话总结

不降级模组格式（保住计划书"能造新机制"），把不可信代码关进 QuickJS-WASM：
**换来的是真计量与真隔离，付出的是包体膨胀与一次必须做的性能 POC**；
而无论最后走哪条路，**内容指纹和存档隔离都必须先做** —— 否则"分享种子"这个
立项卖点会先被 mod 系统自己打穿。
