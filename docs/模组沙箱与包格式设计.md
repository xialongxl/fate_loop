# 模组沙箱与包格式设计

> 状态：**已决策，待实施**（S0 POC 未跑）
> 决策：保留 JS 作为模组语言，第三方包在 **QuickJS-WASM** 里执行
> 起因：要支持"玩家一键加载别人的 mod"（GitHub Pages 无后端），而构建期打包的
> 原生 ESM 模组等于把陌生人的代码放进同源全权环境 —— 这两件事不能同时成立。

---

## 1. 决策记录

### 1.1 为什么必须动

| 事实 | 出处 |
|---|---|
| 模组是构建期打包的（`import.meta.glob` 在 build 时展开成静态 import 图） | 实测：`dist/assets/setup-*.js` 里能 grep 到技能名 |
| 因此"装 mod"目前只有 fork + 重新 build 一条路 | 同上 |
| 产品要求：玩家是来玩的，不是来当极客自己构建的 | 本次讨论的决定性输入 |
| 计划书要求模组能注入**新技能、新怪物、新地图生成逻辑** | 完整设计计划书 第 27 行 |
| 计划书要求"模组作者只能调用契约，不能直接触碰私有状态" | 完整设计计划书 第 253 行 |

关键洞察：**"新机制"只需要一个新的 `execute` 闭包，不需要改 core。** 官方技能由
工厂模板生成的对象，和模组手写的 `execute` 产出的对象是同一种东西。所以只要沙箱
能跑 JS，计划书的全部承诺都能保留 —— 这是放弃"JSON 数据包"方案的根本原因。

### 1.2 被否掉的方案

| 方案 | 否掉的理由 |
|---|---|
| **只支持 fork + 自己 build** | 与"玩家装包"的产品目标冲突 |
| **JSON 数据包 + 固定效果词汇表** | 违反计划书第 27 行：模组不能造新机制。测量显示官方内容 100% 是"4 个工厂 + 6 种谓词 + 11 种操作"，所以 JSON 能覆盖**今天的全部内容** —— 但也就到此为止，词汇表外的一切要等引擎版本 |
| **zip / modpack 容器** | 本项目不需要音频与图片素材，zip 唯一的存在理由不成立。单个自包含 `.js` 文件是更好的分发单元：可读、可 diff、可 hash、粘进文本框就能跑 |
| **不透明源 iframe + Worker 跑整个战斗模拟** | 隔离最强（连卡死都能 terminate），但要把 `BattleEngine` 搬进沙箱 realm，边界重构量最大。列为 C 方案撑不住时的升级路线 |
| **SES / Compartment（同 realm 冻结）** | 改动最小且保住同步调用，但**无法计量** —— 一个 `while(true)` 就冻住整个页面，而"点了别人的包然后必须刷新页面"是玩家不能承受的失败模式 |
| **只做知情同意，不隔离** | 那不是安全，是免责标签。恶意包仍可清存档、注入钓鱼 UI、发请求 |

### 1.3 为什么是 QuickJS-WASM

1. **真计量**：`shouldInterrupt` 回调可以按"已执行指令数 / 已耗时"从宿主侧中断脚本
   → 无限循环从"页面卡死"降级为"这个包被停用"。这是选它而不是 SES 的决定性理由。
2. **内存上限**：`setMemoryLimit` 直接挡掉吃光内存的包。
3. **默认无能力**：VM 里没有 `fetch` / `localStorage` / `document` / `Date` /
   `Math.random`，除非宿主注入。宿主只注入契约函数 → 计划书第 253 行从"纪律"
   变成"物理事实"。
4. **确定性更好**：没有宿主时钟与随机源，mod 的随机只能走 `prng.next` 契约
   → 摇几次骰子变成可审计的。
5. **模组作者体验几乎不变**：写的还是 JS。限制是"不能用 async、不能 import、
   跨边界只能传可序列化值" —— 而我们的契约本来就只传 `{sourceId, targetId, amount}`
   这类纯数据，契合度高。

### 1.4 代价（必须承认）

- **体积**：QuickJS 的 wasm 大约 0.6~1.5MB（取决于构建：sync/asyncify、release/debug）。
  本项目现在 gzip 后主包约 28KB —— 这是**一个数量级的膨胀**。缓解：懒加载（只在
  用户真的启用第三方包时才拉 wasm），官方内容与不装包的玩家完全不受影响。
- **性能**：每次技能释放要跨 JS↔WASM 边界。一场战斗的释放次数在几百到几千量级，
  单次跨界开销是**必须实测**的（S0 POC 的核心问题）。
- **不能自托管 CDN 之外的来源**：wasm 与 loader **必须 vendoring 进仓库**并固定
  版本 + SRI，不能从第三方 CDN 拉 —— 否则"引入沙箱"这件事本身变成新的供应链风险。

## 2. 目标与非目标

**目标**
- G1 玩家能在不 build 的前提下加载第三方包，且包**无法**读取/破坏主存档、无法访问 DOM、无法发网络请求
- G2 包能定义新技能（含新的 `execute` 行为）、Buff、怪物、遭遇、商品、事件、流派，**以及新的地图生成逻辑**
- G3 卡死/吃内存的包只导致该包被停用，不拖垮页面
- G4 装包前后，"同种子同结果"仍然成立，且**内容集合可辨识**（内容指纹）
- G5 官方内容与 fork 作者的原生 ESM 模组路径**完全不变**

**非目标**
- N1 不做在线工坊/订阅源（分发索引留到 S4 之后另案）
- N2 不支持包内素材（音频、图片）—— 没有需求
- N3 不追求"防同 realm 侧信道"级别的对抗性安全（见 §4.3）
- N4 不做包之间互相依赖的解析（第一版每个包自包含）

## 3. 两层模组架构

```
┌─ 第 1 层：原生 ESM 模组（可信） ─────────────────────────┐
│  src/mods/**  →  import.meta.glob  →  构建期打包         │
│  能力：无限制（能 import core，能注册契约实现）           │
│  谁：官方内容、fork 作者、开发者                          │
│  现状：就是今天的样子，不改                               │
└─────────────────────────────────────────────────────────┘

┌─ 第 2 层：运行时包（不可信） ────────────────────────────┐
│  玩家选文件 / 拖拽 / 粘贴文本  →  sha256 + 源码确认       │
│  →  QuickJS-WASM 里求值  →  调 fate.register* 注册内容    │
│  能力：只有宿主注入的契约 + 预算限制                      │
│  谁：下载别人写的包的玩家                                 │
└─────────────────────────────────────────────────────────┘
```

**对计划书 3.2 的修订**：原文"第三方模组与官方模组在加载机制上无任何区别"要改成
"两层机制：官方与开发者走原生 ESM；不可信包走沙箱，能力受限于契约"。
理由：那条"无区别"正是安全问题的来源，而它带来的好处（自举、同一套校验）通过
**两层共用同一个 merge/validate 管线**仍然保留。

## 4. 威胁模型

### 4.1 沙箱挡住的

| 攻击 | 怎么挡 |
|---|---|
| 清/偷存档（IndexedDB、localStorage） | VM 里没有这些全局；且 modded 运行另有独立库（§7） |
| 注入钓鱼 UI、劫持页面 | VM 里没有 `document` |
| 外发数据、打点、SSRF | VM 里没有 `fetch`/`XMLHttpRequest`/`WebSocket` |
| 读时钟破坏确定性 | 没有 `Date`/`performance`；时间只能从 `ctx.virtualTime` 拿 |
| 自己造随机破坏复现 | 没有 `Math.random`（宿主注入受限的 `Math`）；随机只能走 `prng.next` 契约 |
| 无限循环 / 递归爆栈 / 吃内存 | `shouldInterrupt`（指令数 + 墙钟双预算）、`setMemoryLimit`、`stackSizeLimit` |
| 直接改战斗状态 | 跨界只能拿可序列化快照；写状态只能通过契约 |
| 注册超大内容拖垮加载 | 包体与条目数硬上限（§5.4），schema 校验在求值**之前** |

### 4.2 沙箱挡不住的（要靠别的手段）

| 残余风险 | 缓解 |
|---|---|
| 包让游戏变得不合理（1 血小怪给 1e9 经验） | 数值范围校验 + 存档标记"由 mod 产生" + 玩家可一键停用 |
| 文案注入（技能名塞 HTML） | UI 已全量 `escapeHtml`、日志用 `textContent`；**必须加测试守住**（这是包带来的第一个陌生文本源） |
| 恶意但"合法"的内容（把玩家存档进度变没意义） | 内容指纹 + 独立命名空间，玩家随时能看出"这不是原版那一局" |
| 沙箱本身的漏洞（QuickJS/wasm 的 CVE） | 版本固定 + SRI + vendoring，不追新；把 QuickJS 当依赖看待 |
| 供应链：包作者诱导你"再装一个包" | 每个包都要单独确认；不做"信任作者后自动放行" |

### 4.3 明确不承诺的

不做对抗性安全。我们防的是"一个普通恶意/劣质包在玩家不知情时搞坏游戏"，
不防"针对 QuickJS 版本的内存漏洞利用"。文档与 UI 都不该写成"绝对安全"。

## 5. 包格式规范（草案 v1）

### 5.1 一个包 = 一个自包含的 `.js` 文件

```js
// abyss.js —— 第三方包示例
// 运行在 QuickJS 里：没有 import、没有 async、没有宿主全局
fate.begin({
  id: 'someone.abyss',
  version: '1.0.0',
  title: '深渊补充包',
  author: 'someone',
  description: '新流派「深渊」：叠印记、收割、以生命换爆发。',
});

fate.family({ id: 'abyss', label: '深渊' });

fate.buff({
  id: 'abyss.mark', name: '深渊印记', isDebuff: true,
  damageTakenMul: 1.15, description: '每层提升受到伤害 15%。',
});

// 新机制：消耗目标身上全部深渊印记，每层追加 25% 倍率
fate.skill({
  id: 'abyss.reap', name: '收割', type: 'GCD', gcdCost: 2.4,
  range: 'single', tags: ['abyss', 'execute'],
  description: '引爆目标所有深渊印记。',
  execute(ctx, self, targets) {          // 这个函数活在沙箱里
    const damage = ctx.contract('damageApply');
    const stacks = ctx.contract('stateQuery');      // 只读快照
    for (const t of targets) {
      const n = stacks(`monsters.${t.id}.buffs.abyss.mark.stacks`) ?? 0;
      damage({ sourceId: self.id, targetId: t.id, amount: self.attack * (1 + 0.25 * n) });
      if (n > 0) ctx.contract('buffRemove')({ targetId: t.id, buffId: 'abyss.mark' });
    }
  },
});

fate.monster({ id: 'mon.abyss.wisp', name: '深渊游魂', maxHp: 88, attack: 24, defense: 6,
  gcdSequence: ['abyss.reap', 'blade.jab'], tags: ['abyss'] });

fate.encounter({ id: 'enc.abyss.lone', tier: 'normal', monsterIds: ['mon.abyss.wisp'],
  minFloor: 1, maxFloor: 999, weight: 4 });

fate.shopItem({ id: 'shop.abyss.core', name: '深渊核', cost: 60, kind: 'upgrade',
  description: '永久 +6 攻击。',
  apply(state) { fate.permanentBonus({ attack: 6 }); } });   // 宿主提供的安全原语

fate.event({ id: 'event.abyss.whisper', name: '深渊低语', text: '…', weight: 6,
  choices: [
    { label: '听', description: '+30 碎片，但失去 10% 当前生命',
      apply(state) { fate.gainShards(30); fate.hpCostRatio(0.1); } },
    { label: '走开', description: '无事发生', apply() {} },
  ] });

fate.finish();
```

要点：
- **没有 `import`**：包必须自包含。想引用官方技能就用 **ID 字符串**（`'blade.jab'`），
  这与今天官方模组引用 ID 的做法一致。
- `execute` / `apply` 是**真正的函数** → 新机制成立（计划书第 27 行）。
- 商店与事件的 `apply` 里改状态用 `fate.*` 安全原语（内部映射到已有的
  `addPermanentBonus` 等），**不给它 state 对象的写权限**。为什么：`apply` 今天
  直接改 draft，那是 core 内部对象；跨界只能传可序列化值，所以必须换成一等 API。

### 5.2 宿主注入给包的能力清单（白名单，其余一律没有）

| 注入 | 说明 |
|---|---|
| `fate.begin/family/buff/skill/monster/encounter/shopItem/event/generator/finish` | 注册 API |
| `ctx.contract(name)` | 七个契约的包装：`damageApply healApply buffApply stateQuery prngNext combatLog audioPlay`（v1 再加 `buffRemove`） |
| `ctx.virtualTime` `ctx.floorNumber` | 只读，来自引擎 |
| `fate.permanentBonus / gainShards / spendShards / healRatio / hpCostRatio / fullHeal / addMetadata` | 探索态安全原语（对应测出的 11 种操作） |
| `Math`（去掉 `random`）、`JSON`、`Object/Array/String/Number/Boolean`、`Map/Set` | 语言基座 |

**故意不给**：`Date`、`performance`、`fetch`、`Worker`、`document`、`localStorage`、
`indexedDB`、`console`（用 `ctx.log` 代替，走 combatLog 并计入预算）、`eval`/`Function`。

### 5.3 加载流程

```
选文件/拖拽/粘贴
  → 计算 sha256
  → 确认面板：包名、作者、版本、哈希（与来源处公布的比对）、源码全文可展开
  → 求值（QuickJS，预算内；只允许注册，不允许其他副作用）
  → fate.finish() 收集产物
  → 走与官方内容**同一条** normalize + validatePoolReferences 管线
  → 失败：整包拒绝，明确报出是哪条内容哪个字段（复用现有 ModLoadError 文案）
  → 成功：写入已装列表（含哈希），重算 contentHash，提示"本局内容与原版不同"
```

复用现有管线是关键决定：**不为包另写一套校验**。官方内容今天怎么被 normalize
和查悬空引用，包就怎么被处理 —— 这样包作者能拿到和官方一样的报错信息。

### 5.4 硬上限（求值前 + 注册时双重检查）

| 项 | 上限（初值，可调） |
|---|---|
| 包文件体积 | 256 KB |
| 技能 / 怪物 / 遭遇 / Buff / 商品 / 事件 各 | 200 / 500 / 300 / 100 / 50 / 50 |
| 单个字符串（名称/描述/文本） | 200 字符 |
| 数值字段（倍率、cost、maxHp、attack…） | 有限数且 `0 ≤ v ≤ 1e6`；倍率 ≤ 50 |
| 单场战斗里该包的契约调用次数 | 20 000（超出即判定失控并停用该包） |
| 单次 `execute` 的 VM 指令预算 | 50 000 步（`shouldInterrupt`） |
| VM 内存 | 32 MB |

## 6. 引擎侧改造点

1. **新增 `src/mods/sandbox/`**
   - `quickjsRuntime.js`：懒加载 wasm、创建 VM、注入白名单、预算与中断回调
   - `packHostApi.js`：`fate.*` 注册表 + 安全原语
   - `packLoader.js`：文本 → sha256 → 求值 → 产物 → 交给现有 `mergeIntoPool`
   - `packSchema.js`：硬上限与字段校验（复用 `invariant.js` 的断言）
2. **`execute` 调用点要能接受"来自 VM 的函数"**：对调用方透明（还是
   `skill.execute(ctx, self, targets)`），但 ctx 必须是**包装过的**：
   传入的 self/targets 是纯数据快照，返回后由引擎自己应用契约效果。
   ⚠️ 这是唯一可能碰热路径的地方，也是 S0 POC 必须量的东西。
3. **`stateQuery` 契约**：包拿到的必须是纯数据快照（今天它返回深冻结对象，
   跨 VM 需要 `structuredClone` 语义的转换 —— QuickJS 侧要 `dup`/`json` 转换）。
4. **错误与停用**：包内抛错 → 宿主 try/catch → 该包标记 `faulted`，本局停用并提示；
   连续超预算同理。**不允许**一个坏包把整局拖崩（对齐计划书"模组执行异常"条目）。
5. **内容指纹**（§7）与**已装包列表**要进 `state`（或独立的非确定性 UI 层？
   见 §7.2 —— 结论：进存档，不进战斗状态）。

## 7. 内容指纹与存档隔离

### 7.1 contentHash —— 让"抄种子复现"在装包后仍然成立

现在 `结果 = f(seed, 序列, 内容池)`。装包后内容池因人而异，所以复现凭据必须是
**种子 + 内容指纹**：

```
contentHash = fnv1a( 官方内容版本
                   + 每个已装包的 (id, version, sha256) 按 id 排序拼接 )
显示：头部种子旁 · 结算面板 · 历史战绩 · 存档摘要
文案：种子 20240101 · 内容 a1b2c3d4
```

- 哈希取**包源码字节**，不取求值结果（结果可能含函数引用，不稳定）
- 官方内容也要参与：今天 fork 改了官方数值，两个站的种子同样不复现 —— 所以这一项
  **与工坊无关，现在就有价值**（S1 先做的理由）
- 排序必须是 id 字典序，不能依赖加载顺序（与项目一贯的"平局打破靠字典序"同一条纪律）

### 7.2 存档独立命名空间

- 启用任何第三方包时，运行数据写入**另一个 IndexedDB 库**（如 `fate-loop-modded`），
  原版存档所在的 `fate-loop` 完全不被第三方代码路径触达
- 每条存档记录 `contentHash` + 包清单；读档时若清单缺失 → 明确提示
  "这个存档需要这些包：…（缺 X）"，而不是静默用不同内容恢复
- `contentHash` 存在 UI/持久层，**不进 `state` 的战斗字段**：它不是游戏状态，
  进了就会污染快照对拍与确定性断言

### 7.3 为什么顺序上先做这两件

它们和沙箱选型无关、体量小（各 ~100 行）、而且**即使最后不上沙箱也必须做**
（最坏情况的兜底）。先落地它们，后面无论走 C 还是退回 D 都不白干。

## 8. 分发路径（分期）

| 期 | 方式 | 说明 |
|---|---|---|
| S2 | 本地文件 / 拖拽 / 粘贴文本 | 零网络、零 CORS、离线可用，先打通 |
| S4 | 仓库内 `modindex.json`（同源，无 CORS） | 策展列表：id/版本/作者/下载 URL/sha256/简介 |
| S4 | 包本体放 GitHub Release 资产 | ⚠️ CORS 头待实测；不行就退回 jsDelivr 镜像仓库文件 |
| 以后 | 作者自己的 Pages + 索引交叉引用 | 不做中心服务，符合"只挂 Pages" |

**包必须固定 sha256 并显示**：作者改包与作者换包，在玩家眼里必须可区分。

## 9. 实施计划

| 阶段 | 内容 | 量 | 出口条件 |
|---|---|---|---|
| **S0** | **POC**：装 `quickjs-emscripten`，vendoring wasm，跑 3~5 个官方技能样本 | ~200 行 + 依赖 | 实测：包体增量、单次跨界开销、一场 MAX 战斗总耗时、`shouldInterrupt` 真能掐死 `while(true)` |
| **S1** | 内容指纹 + 存档独立命名空间 | ~220 行 | 头部/存档/历史显示 contentHash；关包读档能提示缺失 |

## 11. 一句话总结

不降级模组格式（保住计划书"能造新机制"），把不可信代码关进 QuickJS-WASM：
**换来的是真计量与真隔离，付出的是包体膨胀与一次必须做的性能 POC**；
而无论最后走哪条路，**内容指纹和存档隔离都必须先做** —— 否则"分享种子"这个
立项卖点会先被 mod 系统自己打穿。
